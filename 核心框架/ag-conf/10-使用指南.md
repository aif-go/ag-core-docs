## 快速开始 — 最简单的方式

在应用中获取配置，只需三步：

### 第 1 步：写配置文件

`app.yml`（放在可执行文件同目录下）：

```yaml
app:
  name: my-service
  server:
    port: 8080
  datasource:
    url: jdbc:mysql://localhost:3306/db
    username: root
```

### 第 2 步：定义配置结构体 + 默认值 + 构造函数

每个配置模块按以下模式组织（**结构体 + 默认值函数 + 构造函数** 三件套）：

```go
// config.go — 定义结构体 + 默认值
package config

import "gitlab.allinfinance.com/aifgo/ag-core/ag/ag_conf"

// ---- 常量 key ----

const AppConfigKey = "app"

// ---- 结构体定义（无 value 标签，直接用字段名映射） ----

type AppConfig struct {
    Name       string
    Server     ServerConfig
    Datasource DatasourceConfig
}

type ServerConfig struct {
    Port int
}

type DatasourceConfig struct {
    Url      string
    Username string
}

// ---- 默认值 ----

func DefaultAppConfig() AppConfig {
    return AppConfig{
        Name: "unnamed",
        Server: ServerConfig{
            Port: 8080,
        },
        Datasource: DatasourceConfig{
            Username: "root",
        },
    }
}

// ---- 构造函数（注入 binder，先默认后覆盖） ----

func NewAppConfig(binder ag_conf.IBinder) (*AppConfig, error) {
    cfg := DefaultAppConfig()
    err := binder.Bind(&cfg, AppConfigKey)
    if err != nil {
        return nil, err
    }
    return &cfg, nil
}
```

### 第 3 步：初始化配置

```go
// main.go
package main

import (
    "gitlab.allinfinance.com/aifgo/ag-core/ag/ag_conf"
    "your-project/config"
)

func main() {
    // 1. 创建环境 + 加载本地配置
    env, _ := ag_conf.NewStandardEnvironment()
    ag_conf.LoadLocalConfigToState(env)
    binder := ag_conf.NewConfigurationPropertiesBinder(env)

    // 2. 通过构造函数创建配置（自带默认值，配置文件覆盖）
    cfg, err := config.NewAppConfig(binder)
    if err != nil {
        panic(err)
    }

    // 3. 使用
    println(cfg.Name)
    println(cfg.Server.Port)
}
```

✅ 搞定。这是 ag-conf 推荐的标准使用模式。

## 定义配置结构体

> 推荐使用 **结构体 + 默认值函数 + 构造函数** 三件套模式：

### 标准模式（推荐）

```go
package config

const ServerConfigKey = "app.server"

type ServerConfig struct {
    Port int    // value 标签可选，不指定时用字段名
    Host string
}

func DefaultServerConfig() ServerConfig {
    return ServerConfig{
        Port: 8080,
        Host: "0.0.0.0",
    }
}

func NewServerConfig(binder ag_conf.IBinder) (*ServerConfig, error) {
    cfg := DefaultServerConfig()
    err := binder.Bind(&cfg, ServerConfigKey)
    if err != nil {
        return nil, err
    }
    return &cfg, nil
}
```

**设计要点：**
- **代码写默认值**，不是 YAML。开发时即使没有配置文件也能跑
- **构造函数注入 `binder`**，不依赖全局变量，方便测试
- **返回 `(*Config, error)`**，调用者自行决定启动失败还是继续
- 结构体**不需要 `value` 标签**，字段名直接映射为配置 key

### 方式 1：无标签（推荐）

**最推荐的方式。** 字段名自动映射为配置 key，干净简洁。

```yaml
# app.yml
app:
  name: my-service
  server:
    port: 8080
```

```go
type AppConfig struct {
    Name   string       // ← 自动匹配 app.Name
    Server ServerConfig // ← 自动匹配 app.Server
}

type ServerConfig struct {
    Port int            // ← 自动匹配 app.Server.Port
}
```

**命名规则：** 字段名**保持首字母大写**（Go 导出规则），映射时大小写不敏感。

```yaml
# YAML 中的 key 大小写任意
app:
  NAME: my-service        # 大写也能匹配
  Server:                 # 大小写任意
    PORT: 8080            # 大写也能匹配
```

### 方式 2：指定 key（`value` 标签）

当 YAML key 与字段名不对应时使用：

```yaml
app:
  db_host: localhost     # key 带下划线，无法作为字段名
```

```go
type AppConfig struct {
    DbHost string `value:"${db_host}"`    // 指定映射 db_host
}
```

**当 `value` 标签存在时，root key 会自动拼接：**

| 标签 | root key | 最终 key |
|------|----------|----------|
| `value:"${host}"` | `"app"` | `app.host` |
| `value:"${server.host}"` | `"app"` | `app.server.host` |
| `value:"${host}"` | `""` | `host` |

### 方式 3：指定默认值

```go
type Config struct {
    Port int    `value:"${port:8080}"`     // 找不到时默认 8080
    Host string `value:"${host:localhost}"` // 找不到时默认 localhost
}
```

### 方式 4：只设默认值，key 仍用字段名

```go
type Config struct {
    Port int `value:"${:=8080}"`   // key = "Port"，找不到时默认 8080
}
```

`${:=值}` 的写法表示：key 为空（用字段名），只设默认值。

## 获取配置值的 3 种方式

### 方式 A：绑定到结构体（推荐）

适合有明确配置结构的场景。

```go
type DBConfig struct {
    Host     string
    Port     int    `value:"${port:3306}"`
    Username string
    Password string `required:"true"`
}

var cfg DBConfig
binder.Bind(&cfg, "datasource")
// 从 datasource.host, datasource.port, datasource.username 读取
```

### 方式 B：直接获取属性值

适合不确定结构、只需一两个值的场景。

```go
host := env.GetProperty("datasource.host")
port := env.GetPropertyDefault("datasource.port", "3306")

// 必填，找不到会返回 error
pwd, err := env.GetRequiredProperty("datasource.password")

// 解析占位符
url := env.ResolvePlaceholders("${datasource.host}:${datasource.port}")
```

### 方式 C：从属性源直接读

适合调试或特殊场景。

```go
sources := env.GetPropertySources()
source := sources.Get("[LOCAL]-app.yml")
val := source.GetProperty("datasource.host")
```

## 配置文件怎么写

### 支持的格式

| 格式 | 后缀 | 示例 |
|------|------|------|
| YAML | `.yml` / `.yaml` | 最常用，推荐 |
| JSON | `.json` | |
| Properties | `.properties` | `key=value` 格式 |
| TOML | `.toml` | |

### 默认加载规则

```
可执行文件同目录下的 app.yml
  └── 可通过 app.conf 配置自定义路径
```

```go
// 方式 1：默认路径
app.yml (放在可执行文件旁)

// 方式 2：通过环境变量指定
-Dapp.conf=/etc/myapp/config.yml

// 方式 3：通过系统环境变量指定
export app_conf=/etc/myapp/config.yml
```

### YAML 最佳实践

```yaml
# ⚠️ key 中的 _ 和 . 不要混用
# AgConf 会自动将环境变量中的 _ 转为 .，但 YAML 中建议用 .
# 好的写法：
app:
  db.host: localhost     # 点号访问，与扁平 key 一致

# 更推荐的写法（嵌套结构）：
app:
  db:
    host: localhost      # 展开后为 app.db.host
    port: 3306

# 占位符引用（引用任意 PropertySource 中的值）
app:
  name: my-service
  fullName: ${app.name}-v1       # 引用自己的字段，结果：my-service-v1

# 跨 section 引用（避免重复配置）
nacos:
  config:
    serveraddr: 192.168.1.1:8848
    namespace: aic-dev
  naming:
    serveraddr: ${nacos.config.serveraddr}   # 引用 config 下的值
    namespace: ${nacos.config.namespace}

# 嵌套占位符
app:
  env: dev
  url: http://${app.env}.example.com    # 结果：http://dev.example.com
```

## 配置来源与优先级

配置按以下优先级查找（高优先级覆盖低优先级）：

```
最高优先级
  │
  ├── [SYS]-Properties         ← 命令行 -D 参数（最高，AddBefore 插入到所有源之前）
  ├── [SYS]-Environment        ← 系统环境变量（AddFirst）
  ├── Nacos 远程配置            ← 远程配置中心（AddAfter Environment）
  └── [LOCAL]-app.yml          ← 本地 YAML 文件（AddLast）
  │
最低优先级

> [DECRYPT]-* 为解密后的副本，通过 AddBefore 插入到对应原始源之前，优先级略高于原始源。
```

### 命令行传参

```bash
# 标准格式：-Dkey=value
./myapp -Ddb.host=10.0.0.1 -Dserver.port=9090

# 无等号视为 true
./myapp -Ddebug

# 自定义前缀（通过环境变量 GS_ARGS_PREFIX）
GS_ARGS_PREFIX=-- ./myapp --db.host=localhost
```

### 系统环境变量

```bash
# 环境变量中的 _ 会自动转为 .
export DB_HOST=10.0.0.1      # 映射为 db.host
export DB_PORT=3306           # 映射为 db.port
export SERVER_PORT=9090       # 映射为 server.port

# key 统一转为小写，大小写不敏感
export DB_HOST=10.0.0.1      # 和 Db_Host、db_host 都等效
```

**实际案例：容器部署时覆盖配置**

```yaml
# app.yml 中的默认值
app:
  server:
    port: 8080
  datasource:
    url: jdbc:mysql://localhost:3306/db
```

```bash
# 容器启动时通过环境变量覆盖
docker run -e SERVER_PORT=9090 \
           -e DATASOURCE_URL=jdbc:mysql://prod-host:3306/proddb \
           myapp
```

### 声明必填字段

```go
type Config struct {
    Host     string `required:"true"`             // 必填
```

```go
// 方式 1：Bind 时自动校验
binder.Bind(&cfg, "app")

// 方式 2：主动校验
env.SetRequiredProperties("db.host", "db.password")
err := env.ValidateRequiredProperties()
```

```go
type Config struct {
    // name[0] 必填，name[1]、name[2]... 可选
```

## 配置绑定与使用细节

### 绑定时的 key 推导规则

```go
binder.Bind(&cfg, "app")
```

| 字段定义 | 查找的 key |
|----------|------------|
| `Name string` | `app.Name`（root + 字段名） |
| `Name string \`value:"${host}"\`` | `app.host`（root + 标签 key） |
| `Name string \`value:"${:=default}"\`` | `app.Name`（root + 字段名，有默认值） |

### 支持的类型对照

```yaml
app:
  name: my-service          # → string
  count: 3                  # → int
  rate: 0.75                # → float64
  enabled: true             # → bool
  tags:                     # → []string
    - "go"
    - "microservice"
  options:                  # → map[string]string
    timeout: 30
    retry: 3
  servers:                  # → []ServerConfig（切片结构体）
    - host: node1           #   key = app.servers[0]
      port: 8080            #   key = app.servers[0].port
    - host: node2           #   key = app.servers[1]
      port: 8081            #   key = app.servers[1].port
```

```go
type Config struct {
    Name    string
    Count   int
    Rate    float64
    Enabled bool
    Tags    []string
    Options map[string]string

    Servers []struct {
        Host string
        Port int
    }
}
```

### 嵌套结构体的处理

```go
type AppConfig struct {
    Name   string
    Server ServerConfig          // 子结构体递归绑定
}

type ServerConfig struct {
    Port int
    Host string
}
// 绑定时自动查找 app.Name, app.Server.Port, app.Server.Host
```

### 匿名字段

```go
type BaseConfig struct {
    Env string
}

type AppConfig struct {
    BaseConfig                      // 匿名字段，字段直接提升
    Name string
}
// 绑定时查找 app.Env, app.Name
```

### 指针类型

```go
type Config struct {
    Server *ServerConfig     // 指针类型，自动解引用
}

func main() {
    cfg := Config{}
    // 即使 Server 是 nil 指针也能绑定
    binder.Bind(&cfg, "app")
}
```

### 切片（数组）类型

```go
type Config struct {
    Nodes []NodeConfig `value:"${nodes}"`
}

type NodeConfig struct {
    Host string
    Port int
}
```

```yaml
app:
  nodes[0]:
    host: node1
    port: 8080
  nodes[1]:
    host: node2
    port: 8081
```

或扁平写法：

```yaml
app:
  nodes[0].host: node1
  nodes[0].port: 8080
  nodes[1].host: node2
  nodes[1].port: 8081
```

### Map 类型

```yaml
app:
  redis:
    shard1: 10.0.0.1:6379
    shard2: 10.0.0.2:6379
    shard3: 10.0.0.3:6379
```

```go
type Config struct {
    Redis map[string]string `value:"${redis}"`
}
// cfg.Redis["shard1"] = "10.0.0.1:6379"
```

## 配置热更新

### 自动刷新（无需额外代码）

**所有通过 `Binder.Bind()` 绑定的配置项默认自动参与热更新。**

```go
// 启动时绑定
binder.Bind(&cfg, "app")

// Nacos 配置变更后 → cfg 自动更新
// 本地文件变更后 → cfg 自动更新（需文件 Watcher）
```

不需要写任何刷新逻辑。

### 手动注册监听器

如果不想用绑定，也可以手动监听某个 key 的变化：

```go
import "gitlab.allinfinance.com/aifgo/ag-core/ag/ag_conf"

ag_conf.WatcherM.RegChangeListener("db.host", func(key, value string) {
    // 当 db.host 变化时，在这里处理
    println("db.host changed to:", value)
})
```

### 使用

```go
// main.go — 手动组装
package main

import (
    "log"
    "your-project/config"
    "your-project/app"

    "gitlab.allinfinance.com/aifgo/ag-core/ag/ag_conf"
)

func main() {
    // 1. 初始化配置环境
    env, _ := ag_conf.NewStandardEnvironment()
    ag_conf.LoadLocalConfigToState(env)
    binder := ag_conf.NewConfigurationPropertiesBinder(env)

    // 2. 创建各模块配置
    dbCfg, err := config.NewDbConfig(binder)
    if err != nil {
        log.Fatalf("db config: %v", err)
    }

    redisCfg, err := config.NewRedisConfig(binder)
    if err != nil {
        log.Printf("redis config incomplete, running without cache: %v", err)
        // redis 可降级，不 fatal
    }

    // 3. 启动应用（配置已就绪）
    app := app.New(dbCfg, redisCfg)
    app.Run()
}
```

## 常见问题

### Q: 字段找不到值但没报错？

这是正常行为。Binder 对**没有 `required` 标签**的字段，找不到值时**静默跳过**，字段保持 Go 零值。

```go
type Config struct {
    Host string  // 找不到时 = ""（零值）
}
```

需要严格模式？加 `required:"true"`：

```go
type Config struct {
    Host string `required:"true"` // 找不到时返回 ErrNotExist
}
```

### Q: 我改了 app.yml，应用需要重启吗？

- 本地文件修改 → 默认不会自动重新加载（不重启不会感知）
- 使用 Nacos 远程配置 → 自动热更新，无需重启
- 通过环境变量或 `-D` 参数 → 必须重启

### Q: `_` 和 `.` 的规则是什么？

| 来源 | 规则 |
|------|------|
| YAML key | 按原样使用，`.` 表示嵌套 |
| 环境变量 | **`_` 自动转为 `.`**，`DB_HOST` → `db.host` |
| 命令行 `-D` | 按原样使用 |
| struct 字段名 | 不转换，`_` 保留 |

所以如果你有环境变量 `DB_HOST`，在 YAML 中应该用 `db.host` 来引用，在代码中用 `db.host` 来读取。

### Q: 多个同 key 配置，到底用哪个？

按优先级：**命令行 > 环境变量 > 配置文件**。高优先级的值覆盖低优先级。

```yaml
# app.yml 中
server:
  port: 8080
```

```bash
# 命令行覆盖
./myapp -Dserver.port=9090   # 实际值是 9090

# 环境变量覆盖（比配置文件高，比 -D 低）
export SERVER_PORT=7070       # 如果去掉 -D 参数，实际值是 7070
```

### Q: 怎么调试配置加载？

开启 debug 日志可以看到每个 key 的查找过程：

```go
// 在 main.go 中设置
slog.SetLogLoggerLevel(slog.LevelDebug)
```

然后就能看到：

```
DEBU Searching for key 'app.name' in PropertySource '[SYS]-Properties'
DEBU Searching for key 'app.name' in PropertySource '[SYS]-Environment'
DEBU Searching for key 'app.name' in PropertySource '[LOCAL]-app.yml'
DEBU Found key 'app.name' in PropertySource '[LOCAL]-app.yml'
```

### Q: Binder 是全局单例吗？

是的。`NewConfigurationPropertiesBinder(env)` 会设置全局的 `ag_conf.Binder`。

```go
// 任意地方都可以直接使用
ag_conf.Binder.Bind(&cfg, "app")
```

### Q: Bind 时 root key 传空字符串会怎样？

```go
binder.Bind(&cfg, "")  // root key 为空
```

配置 key 直接从字段名或 value 标签开始，不会有前缀：

```go
type Config struct {
    Name string              // key = "Name"（不是 ".Name"）
    Host string `value:"${host}"`  // key = "host"
}
```

适合需要精确控制 key 的场景。

### Q: 为什么 `value:"${:=8080}"` 的 key 是空的？

ParseTag 解析到 `${:=8080}` 时，key 部分在 `${` 和 `:` 之间为空字符串。BindTag 检测到 `parsedTag.Key == ""` 但 `parsedTag.HasDef == true`，于是只保存默认值，key 保持为 `param.Key` 不变。随后代码走到"使用字段名"的分支，所以最终 key 是字段名。
