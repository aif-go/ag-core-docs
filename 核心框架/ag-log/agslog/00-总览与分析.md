## 关键设计哲学

1. **懒初始化**：Builder 在 `init()` 中创建时是空的，所有 handler/factory 都是后续注册
2. **透过原子指针访问**：TopLogger 的 Handler() 永远是 ReplaceableHandler，内部指针可以热替换
3. **名称即契约**：通过名称解析 handler，支持递归依赖和延迟创建
4. **双阶段初始化**：init 阶段创建最小可用 Logger，Build 阶段注入真实 handler 链

## 对比 Java 日志体系

`agslog.GetSlogByName("name")` 是 agslog 面向应用的核心 API，其设计直接对标 Java 日志体系：

| Java | agslog | 说明 |
|------|--------|------|
| `LoggerFactory.getLogger("name")` | `agslog.GetSlogByName("name")` | 按名称获取 Logger 实例 |
| `LoggerFactory.getLogger(Xxx.class)` | `agslog.GetSlogByName("模块名")` | 模块/类级别的日志隔离 |
| logback.xml / log4j2.xml | `aglog.*` 配置 | 外部化日志配置 |
| Appender | `slog.Handler`（zap/text/console） | 日志输出目标 |
| Logger hierarchy | `NamedHandler` 名称体系 | 按名称组织 Logger 树 |
| AsyncAppender | `async.AsyncHandler` | 异步日志处理 |
| MDC | `slog.Context` + `AttrFromContext` | 上下文日志属性 |

**核心思想**：应用代码通过名称获取 Logger，不关心底层的 Appender 组合和配置。日志管道的装配全部外部化到配置中，与业务代码解耦。`GetSlogByName` 之于 agslog，就像 `LoggerFactory.getLogger` 之于 SLF4J。
