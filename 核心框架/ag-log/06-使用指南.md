## 快速开始 — 最简单的方式

在你的应用中打日志，只需两步：

### 第 1 步：引入 FX Module

```go
import (
    "gitlab.allinfinance.com/aifgo/ag-core/ag/ag_log"
    "gitlab.allinfinance.com/aifgo/ag-core/fxs"
    "go.uber.org/fx"
)

func main() {
    fxapp := fx.New(
        fxs.FxAgConfModule,     // 加载配置
        ag_log.FxAglogMode,     // 装配日志系统
    )
    fxapp.Run()
}
```

### 第 2 步：在业务代码中打日志

```go
import (
    "context"
    "gitlab.allinfinance.com/aifgo/ag-core/ag/ag_log/agslog"
)

func BizHandler(ctx context.Context) {
    logger := agslog.GetSlog()   // 获取顶层 Logger
    logger.InfoContext(ctx, "业务处理完成", "order_id", "12345", "amount", 100.50)
}
```

✅ 搞定。默认输出到控制台（JSON 格式）。

> **💡 最佳实践：始终使用 `InfoContext`** — 通过 `context.Context` 传入 traceId、requestId 等上下文信息，日志系统会自动提取并附加到每条日志。详见 [[#上下文日志属性（MDC）|MDC 章节]]。

## 配置日志

### 最小配置

`app.yml`：

```yaml
aglog:
  isDefault: true                            # 替换 slog 全局默认
  topHandler:
    - "default"                              # 顶层 handler 名称
  zap:
    logs:
      default:
        log_level: debug
        stdout: true                         # 输出到控制台
        console: true                        # 人类可读格式（带颜色）
```

### 完整配置参考

```yaml
aglog:
  # 是否替换 slog 全局默认（默认 true）
  isDefault: false

  # 顶层 handler 列表（名称引用）
  topHandler:
    - "console"
    - "file"

  # === zap 输出后端 ===
  zap:
    logs:
      console:                         # handler 名称
        log_level: debug
        stdout: true
        console: true                  # 控制台彩色输出
      file:
        log_level: info
        log_file_name: "logs/app.log"  # 日志文件路径
        max_size: 512                  # 单文件最大 MB
        max_backups: 30                # 最多保留 30 个备份
        max_age: 7                     # 保留 7 天
        compress: true                 # 压缩归档

  # === 扇出路由（复合 handler）===
  fanout:
    logs:
      all: ["console", "file"]         # 同时输出到控制台和文件

  # === 异步日志 ===
  async:
    groups:
      default:
        worker: 2
        queue: 10000
        fullStrategy: drop_new
    logs:
      async_log:
        group: default
        log: all
```

## 获取 Logger 的 2 种方式

### 方式 A：顶层 Logger（简单场景）

```go
import "gitlab.allinfinance.com/aifgo/ag-core/ag/ag_log/agslog"

// 获取全局顶层 Logger
logger := agslog.GetSlog()
// 等价于：
logger := agslog.TopLogger()

logger.Info("全局日志")
```

适合工具函数、临时调试、不关心模块归属的场景。

### 方式 B：按名称获取 Logger（推荐）

```go
// 在模块/包内部定义常量
const LoggerName = "order-service"

// 获取名称对应的 Logger
logger := agslog.GetSlogByName(LoggerName)

logger.Info("订单服务已启动")
```

适合大型项目中每个模块使用独立 Logger。名称在配置中关联 handler 链，**同一个名称始终拿到同一个 Logger 实例**（线程安全、可缓存）。

## 打日志

> ⭐ **推荐优先使用 `XxxContext` 系列方法**（`InfoContext` / `DebugContext` / `WarnContext` / `ErrorContext`），将 `context.Context` 传入日志系统，自动携带 traceId、requestId 等上下文信息。

### 首选用法（带 context，推荐）

```go
// 始终传入 context，框架自动提取 trace 信息
logger.InfoContext(ctx, "用户登录",
    "user_id", 10086,
    "ip", "10.0.0.1",
)
logger.ErrorContext(ctx, "数据库错误", "err", err)
logger.DebugContext(ctx, "调试信息")
logger.WarnContext(ctx, "磁盘警告", "usage", "85%")
```

### 不带 context（简单场景）

当确实没有 context 可用时（如工具函数、启动日志），使用无 context 版本：

```go
logger.Info("服务启动完成", "version", "1.0.0")
logger.Warn("配置缺失，使用默认值", "key", "timeout")
logger.Error("初始化失败", "err", err)
```

### 带分组

```go
logger.WithGroup("request").
    With("method", "POST").
    With("path", "/api/order").
    InfoContext(ctx, "收到请求")
```

输出：

```json
{"level":"INFO","msg":"收到请求","request.method":"POST","request.path":"/api/order"}
```

## 模块专属日志（推荐）

每个业务模块拥有独立的 Logger，配置独立输出目标（不同文件、不同级别）。

### 第 1 步：配置中注册多个 zap handler

```yaml
aglog:
  topHandler:
    - "trade_log"
  zap:
    logs:
      trade_log:
        log_level: info
        log_file_name: "logs/trade.log"
        console: true
      heartbeat_log:
        log_level: info
        log_file_name: "logs/heartbeat.log"
      error_log:
        log_level: warn
        log_file_name: "logs/error.log"
```

### 第 2 步：业务模块按名称获取

```go
// 交易模块
tradeLog := agslog.GetSlogByName("trade_log")
tradeLog.InfoContext(ctx, "订单创建", "order_id", "O20250101")

// 心跳模块
heartbeatLog := agslog.GetSlogByName("heartbeat_log")
heartbeatLog.InfoContext(ctx, "心跳正常", "node", "192.168.1.1")

// 全局错误
errLog := agslog.GetSlogByName("error_log")
errLog.ErrorContext(ctx, "数据库连接失败", "err", err)
```

**效果**：交易日志 → `trade.log`，心跳日志 → `heartbeat.log`，错误日志 → `error.log`。完全隔离。

## 多输出：同时写文件和控制台

### 方式 1：单 handler 同时输出

```yaml
zap:
  logs:
    mylog:
      log_file_name: "logs/app.log"
      stdout: true         # 同时输出到控制台
      console: true        # 控制台用彩色格式
```

### 方式 2：Fanout 组合（推荐）

```yaml
aglog:
  topHandler:
    - "all"
  zap:
    logs:
      console_handler:
        log_level: debug
        stdout: true
        console: true
      file_handler:
        log_level: info
        log_file_name: "logs/app.log"
        max_size: 512
  fanout:
    logs:
      all: ["console_handler", "file_handler"]   # 同时去两个
```

**效果**：控制台输出所有 debug 日志，文件只记录 info 及以上。

## 异步日志（高性能场景）

适用于高频日志（> 1000 TPS）的场景，避免日志写入阻塞业务 goroutine。

### 配置

```yaml
aglog:
  topHandler:
    - "asynclog"
  async:
    groups:
      fast:
        worker: 2          # 2 个并发 worker
        queue: 10000       # 队列容量
        fullStrategy: drop_new   # 队列满时丢弃新日志
    logs:
      asynclog:
        group: fast
        log: console        # 异步包装 console handler
  zap:
    logs:
      console:
        log_level: debug
        stdout: true
```

### 使用（与同步日志完全一致）

```go
logger := agslog.GetSlogByName("asynclog")
logger.InfoContext(ctx, "异步写入，立即返回")  // 不阻塞
// 推荐始终使用 InfoContext，即使异步场景，ctx 中的 traceId 也会传递给 worker 线程
```

### 满策略选择

| 策略 | 行为 | 适合场景 |
|------|------|----------|
| `drop_new`（默认） | 队列满时丢弃新日志 | 高吞吐辅助日志，可丢 |
| `block_wait` | 队列满时阻塞等待 | 关键业务日志，不能丢 |
| `drop_old` | 队列满时丢弃最旧的日志 | 优先保留最新日志 |

### 获取统计信息

```go
// 查看异步处理情况
if rh, ok := logger.Handler().(*agslog.ReplaceableHandler); ok {
    if ah, ok := rh.Original().(*async.AsyncHandler); ok {
        stats := ah.GetStats()
        fmt.Printf("入队=%d 已处理=%d 丢弃=%d\n",
            stats.Queued.Load(), stats.Processed.Load(), stats.Dropped.Load())
    }
}
```

## 上下文日志属性（MDC）— 配合 InfoContext

> 类似于 Java 的 MDC（Mapped Diagnostic Context），从 `context.Context` 中提取日志属性自动附加到每条 `InfoContext` / `ErrorContext` / `DebugContext` 调用。

这是 **`InfoContext` 的核心价值所在**——不需要在每个地方手动传 traceId，只需统一设置一次提取逻辑。

### 第 1 步：定义属性提取函数

```go
func TraceIdFromContext(ctx context.Context) []slog.Attr {
    traceId := ctx.Value("trace_id")
    if traceId == nil {
        return nil
    }
    return []slog.Attr{
        slog.String("trace_id", traceId.(string)),
    }
}
```

### 第 2 步：注入中间件

```go
fx.Provide(
    fx.Annotate(
        func() slogmulti.Middleware {
            return func(next slog.Handler) slog.Handler {
                return &traceMiddleware{next: next}
            }
        },
        fx.ResultTags(`group:"agslog.middleware"`),
    ),
)
```

### 第 3 步：写入 context

```go
ctx := context.WithValue(context.Background(), "trace_id", "trace-abc-123")
logger.InfoContext(ctx, "处理请求")  // 自动带上 trace_id
```

## 日志级别与格式

### 级别

| slog 级别 | Zap 级别 | 说明 |
|-----------|----------|------|
| `Debug` | `debug` | 调试信息，开发时使用 |
| `Info` | `info` | 普通信息，默认级别 |
| `Warn` | `warn` | 警告信息，不一定是错误 |
| `Error` | `error` | 错误信息，需要关注 |

### 格式

```yaml
zap:
  logs:
    console_handler:
      console: true    # 控制台格式：彩色、人类可读
    json_handler:
      console: false   # JSON 格式：机器可解析
```

控制台格式示例：
```
2026-05-27 10:30:00.123456789  INFO  main 订单创建 order_id=O20250101
```

JSON 格式示例：
```json
{"ts":1716781800,"level":"INFO","logger":"order","msg":"订单创建","order_id":"O20250101"}
```

## 文件轮转配置

使用 `lumberjack` 实现日志文件轮转：

```yaml
zap:
  logs:
    app_log:
      log_file_name: "logs/app.log"   # 日志文件路径
      max_size: 512                     # 单文件最大 MB（默认 100）
      max_backups: 30                   # 保留备份数（0 = 不限）
      max_age: 7                        # 保留天数（0 = 不限）
      compress: true                    # 压缩归档
```

轮转行为：
- 文件超过 `max_size` → 自动重命名 `app.log` → `app.log.2026-05-27.1.gz`
- 达到 `max_backups` → 删除最旧的备份
- 超过 `max_age` → 删除过期备份

### 开发环境 vs 生产环境

| 维度 | 开发环境 | 生产环境 |
|------|---------|---------|
| 级别 | debug | info |
| 格式 | console（彩色） | JSON |
| 输出 | stdout + file | file only |
| 轮转 | 不轮转 | 按大小/时间轮转 |
| 异步 | 不异步 | 高频模块开异步 |

### Do's and Don'ts

```go
// ✅ 推荐的写法（始终用 InfoContext 携带 context）
logger.InfoContext(ctx, "订单创建成功", "order_id", id, "amount", amount)
logger.With("request_id", reqID).InfoContext(ctx, "处理请求")

// ❌ 差的写法
logger.InfoContext(ctx, fmt.Sprintf("订单创建成功 order_id=%s amount=%f", id, amount))
// → 结构化日志不是文本拼接！属性要分开传，便于日志系统解析

// ❌ 应该用 InfoContext 却用了 Info（丢失上下文）
logger.Info("用户登录", "user_id", 10086)  // 没有 ctx，traceId 等信息丢失
// → 应该改为：logger.InfoContext(ctx, "用户登录", "user_id", 10086)

// ❌ 日志级别滥用
logger.Info("数据库查询超时", "timeout_ms", 5000)  // 应该用 Error 或 Warn

// ❌ 高频循环中打 Info
for _, item := range items {
    logger.Info("处理项目", "id", item.ID)  // 大量日志挤爆磁盘
}
// → 改为 Debug，或限制频率
```

### 应用关闭前确保日志刷完

```go
// FX 应用的 Invoke 可以确保日志在 Shutdown 前刷完
fx.Invoke(func(lifecycle fx.Lifecycle) {
    lifecycle.Append(fx.Hook{
        OnStop: func(ctx context.Context) error {
            slog.Info("应用关闭，等待日志刷盘")
            time.Sleep(100 * time.Millisecond)
            return nil
        },
    })
})
```

## 常见问题

### Q：启动后没有日志输出？

检查：
1. `aglog.topHandler` 是否有配置 handler 名称
2. handler 名称是否在 `aglog.zap.logs` 中定义
3. `log_level` 是否为 `debug`/`info`/`warn`/`error`
4. `stdout: true` 或指定了 `log_file_name`

### Q：日志级别不生效？

`ZlogProperties.log_level` 控制的是**zap 底层级别过滤**，不是 slog 的。slog 层面没有额外级别过滤，所有日志都会送到 zap，由 zap 的级别决定是否输出。

### Q：多个模块的日志能分文件吗？

能。每个 `aglog.zap.logs` 下的条目代表一个 handler，每个 handler 可以指向不同的文件。通过 `GetSlogByName("handler名称")` 获取对应 Logger。

```yaml
aglog.zap.logs:
  trade:    # → GetSlogByName("trade") → 写入 trade.log
    log_file_name: "logs/trade.log"
  system:   # → GetSlogByName("system") → 写入 system.log
    log_file_name: "logs/system.log"
```

### Q：异步日志丢日志怎么办？

- `drop_new` 策略在高并发下不可避免会丢。换成 `block_wait` 保不丢，但业务可能被阻塞
- 增大 `queue` 容量、增加 `worker` 数量可以缓解
- 监控 `Dropped` 统计，设置告警

### Q：和标准 `slog` 兼容吗？

完全兼容。`agslog.GetSlog()` 返回标准 `*slog.Logger`。如果配置了 `isDefault: true`，`slog.Info()` 全局调用也会走 ag-log 的日志管道。

```go
// 以下两行等价（当 isDefault=true 时）
slog.Info("hello")                    // 全局 slog 调用
agslog.TopLogger().Info("hello")      // agslog 调用
```
