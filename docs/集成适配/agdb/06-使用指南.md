# Agdb 使用指南

> 面向业务开发者：快速上手、配置、CRUD、事务、最佳实践

---

## 快速开始

### 1. 添加依赖

项目 `go.mod` 中引入 ag-core 及相关数据库驱动：

```go
require (
    github.com/aif-go/ag-core latest
    gorm.io/gorm v1.x
    gorm.io/driver/mysql v1.x       // MySQL 驱动
    // github.com/ZhengweiHou/gorm_ibmdb  // DB2 驱动
)
```

### 2. 注册 FX 模块

在应用启动代码中注册 agdb 模块（顺序重要）：

```go
import (
    "github.com/aif-go/ag-core/fxs"
    "github.com/aif-go/ag-core/contribute/agdb"
    "github.com/aif-go/ag-core/contribute/agdb/gormdb"
)

func main() {
    app := fxs.FxAppMode(          // 或 fxs.FxHelloServerMode
        // ... 其他模块（配置、日志等）
        gormdb.FxAicGromdbModule,  // 第一步：注册 GORM 连接和 Repository
        agdb.FxAgDbModule,         // 第二步：注册事务中间件和 DAO
    )
    app.Run()
}
```

### 3. 注入 Repository

在 service 中直接注入 `*gormdb.Repository`：

```go
type MyService struct {
    repo *gormdb.Repository
}

func NewMyService(repo *gormdb.Repository) *MyService {
    return &MyService{repo: repo}
}
```

## 配置

### 基础配置

```yaml
# app.yml
data:
  db:
    user:
      driver: mysql               # 已注册的驱动名，默认支持 mysql | ibmdb，详见 02-gormdb.md DBOpener 机制
      dsn: "user:pass@tcp(host:port)/dbname?charset=utf8&parseTime=True"
    pool:
      maxIdleConns: 10
      maxOpenConns: 100
      connMaxLifetime: 3600       # 秒，0 表示不限制
      connMaxIdleTime: 600        # 秒，0 表示不限制
    logger:
      name: agdb                  # 日志名称，对应 agslog 的命名 logger
      debug: false                # true 时开启 SQL 日志（LogLevel=Info）
```

### 多数据源配置

如需多数据库，注册多个 FX 模块：
- 创建多个 `*Config` 实例（不同前缀）
- 创建多个 `*gorm.DB` 和 `*Repository` 实例
- 通过 FX 命名注入区分

## 基本 CRUD

### 上下文感知的 DB 获取

```go
// 使用 Repository.DB(ctx) 获取数据库连接
// 如果当前在事务中，自动返回事务 DB
func (s *MyService) FindByID(ctx context.Context, id int64) (*User, error) {
    var user User
    err := s.repo.DB(ctx).Where("id = ?", id).First(&user).Error
    if err != nil {
        return nil, err
    }
    return &user, nil
}
```

### 创建

```go
func (s *MyService) Create(ctx context.Context, user *User) error {
    return s.repo.DB(ctx).Create(user).Error
}
```

### 更新

```go
func (s *MyService) Update(ctx context.Context, user *User) error {
    return s.repo.DB(ctx).Model(user).Updates(user).Error
}
```

### 删除

```go
func (s *MyService) Delete(ctx context.Context, id int64) error {
    return s.repo.DB(ctx).Delete(&User{}, id).Error
}
```

### 带分页查询

```go
func (s *MyService) List(ctx context.Context, pageNum, pageSize int64) ([]User, int64, error) {
    var users []User
    var total int64

    db := s.repo.DB(ctx).Model(&User{})

    // 统计总数
    db.Count(&total)
    if total == 0 {
        return nil, 0, nil
    }

    // 分页
    offset := (pageNum - 1) * pageSize
    err := db.Offset(int(offset)).Limit(int(pageSize)).Find(&users).Error
    return users, total, err
}
```

## 事务使用

事务通过**声明式中间件**自动管理，不需要在业务代码中手动开启/提交事务。

### 声明式事务（推荐）

在 `init()` 中通过 `CallInfo.AddTag` 注册事务标记，事务中间件自动处理开启/提交/回滚：

#### REQUIRED 模式（写操作）

```go
import (
    "your-project/internal/svcgen"
    "github.com/aif-go/ag-core/contribute/agdb"
)

func init() {
    // 写入操作：没有事务时自动开启新事务，有事务则复用
    svcgen.StudentServiceCreateStudentCallInfo.AddTag(agdb.TransactionTag, true)
}
```

`AddTag(agdb.TransactionTag, true)` 等价于 `TRANSACTION_PROPAGATION_REQUIRED`。

#### SUPPORTS 模式（只读/读写混合）

```go
svcgen.StudentServiceGetStudentCallInfo.AddTag(
    agdb.TransactionTag, agdb.TRANSACTION_PROPAGATION_SUPPORTS)
```

`SUPPORTS` 表示：有上层事务则加入，无事务则以非事务方式执行。适合只读查询或既可单独调用也可嵌入事务的场景。

**重要**：`CallInfo` 变量在 `svcgen` 包中由 protobuf 代码生成，以 `{Service}{Method}CallInfo` 命名。在 `init()` 中注册后，事务中间件会在每次请求到达时自动处理。

### 事务传播行为

```go
const (
    TRANSACTION_PROPAGATION_REQUIRED  // 必须: 有事务则加入，无事务则开启新事务（默认）
    TRANSACTION_PROPAGATION_SUPPORTS  // 支持: 有事务则加入，无事务则非事务方式执行
)
```

- 注册 `transaction: true` → 等效 `REQUIRED`
- 注册 `transaction: TRANSACTION_PROPAGATION_SUPPORTS` → 指定传播行为

### 在 Biz 层使用

Biz 层注入的是 **DAO 接口**（如 `dao.IStudentDao`），不直接持有 `*gormdb.Repository`：

```go
type StudentBiz struct {
    studentDao dao.IStudentDao  // DAO 接口，不是 Repository
}

func (b *StudentBiz) CreateStudent(ctx context.Context, req *CreateStudentRequest) error {
    // ✅ 直接调用 DAO 方法，事务由中间件自动管理
    _, err := b.studentDao.InsertOne(ctx, m)
    return err
}
```

Biz 层**不需要、也不应该**手动管理事务。只需正常调用 DAO 方法，`DB(ctx)` 会通过 context 自动感知当前是否有事务。

### 手动事务

目前**没有提供**通过 DAO 接口使用手动事务的途径。如果确有需要手动控制事务边界的场景（如批量操作），需要通过 `*gormdb.Repository` 直接使用 GORM：

```go
// 仅在注入 *gormdb.Repository 的层可用（如 service 层或 adapter 层）
err := repo.Transaction(ctx, func(txCtx context.Context) error {
    // DB(txCtx) 自动使用事务连接
    repo.DB(txCtx).Create(&user)
    return nil
})
```

> 但对于标准 gen-go-db DAO 使用场景，建议优先使用声明式事务，避免手动管理。

## 命名 SQL

```go
import "github.com/aif-go/ag-core/contribute/agdb/gormdb"

// 1. 定义参数结构体（字段名与 SQL 中的 @ParamName 对应）
type QueryArg struct {
    Id       int64
    Name     string
    Statuses []int
}

// 2. 编写命名 SQL（支持 Go template 语法）
const sqlTmpl = `SELECT * FROM users
WHERE id = @Id
  AND name = @Name
  AND status IN ( @Statuses )`

// 3. 渲染并执行
func (s *MyService) Query(ctx context.Context, arg QueryArg) ([]User, error) {
    // 步骤1：渲染模板（如需模板语法）
    rawSQL, _ := gormdb.RendSql(sqlTmpl, arg)

    // 步骤2：替换命名参数为 ?
    sql, paramNames := gormdb.ReplaceNamedParamsWithIn(rawSQL)

    // 步骤3：从结构体提取参数值
    params, _ := gormdb.GetParamsByNames(arg, paramNames)

    // 步骤4：执行原始 SQL
    var users []User
    err := s.repo.DB(ctx).Raw(sql, params...).Scan(&users).Error
    return users, err
}
```

> **注意：** `@Statuses` 会被替换为 `?`，GORM 会自动将切片展开为 `IN (?, ?, ?)`。

## WHERE 条件构建

### 链式构建

```go
import "github.com/aif-go/ag-core/contribute/agdb/conditonwhere"

builder := conditonwhere.NewWhereClauseBuilder()
sql, args, _ := builder.
    Eq("status", 1).
    Or().
    BeginGroup().
        Gte("amount", 100).
        Lt("amount", 500).
    EndGroup().
    Build()

// 应用到 GORM
users := s.repo.DB(ctx).Where(sql, args...).Find(&users)
```

### FieldMask 动态过滤

```go
// 定义 WHERE 条件配置（通常在 init 中注册）
conditonwhere.RegisterWhereConfig("FindByOrder", &conditonwhere.MaskWhereCondition{
    Operator: "AND",
    Conditions: []conditonwhere.MaskWhereCondition{
        {Expr: "ORDER_ID = @OrderId"},
        {Expr: "MERCHANT_ID = @MerchantId"},
        {Expr: "STATUS = @Status"},
    },
})

// 在查询中动态过滤
fm := conditonwhere.NewFieldMask()
if req.OrderId > 0 { fm.Set("OrderId") }
if req.MerchantId != "" { fm.Set("MerchantId") }

sql, err := fm.BuildWhereFromConfig("FindByOrder", conditonwhere.WhereConfigMap)
users := s.repo.DB(ctx).Where(sql).Find(&users)
```

## 最佳实践

### ✅ Repository 注入

```go
// 推荐：注入 *gormdb.Repository（包含事务管理能力）
type OrderService struct {
    repo *gormdb.Repository
}

// 所有 DB 操作使用 repo.DB(ctx)
func (s *OrderService) Get(ctx context.Context, id int64) (*Order, error) {
    var order Order
    err := s.repo.DB(ctx).Where("id = ?", id).First(&order).Error
    return &order, err
}
```

### ✅ 声明式事务优先

在 `init()` 中通过 `svcgen.XxxCallInfo.AddTag` 声明事务，而非手动 `Transaction()`：

```go
func init() {
    svcgen.StudentServiceCreateStudentCallInfo.AddTag(agdb.TransactionTag, true)
}
```

- 代码更简洁
- 事务边界由中间件自动管理
- 支持传播行为（REQUIRED / SUPPORTS）
- Biz 层无需关心事务，只专注业务逻辑

### ✅ 上下文传递

始终将 `ctx context.Context` 作为第一个参数传递，确保：
- 事务传播正常工作
- 日志上下文绑定
- 请求级超时控制

### ❌ 避免使用全局 DB

```go
// ❌ 不要这样
var db *gorm.DB
db.Where("id = ?", id).First(&user)

// ✅ 总是通过 Repository.DB(ctx)
repo.DB(ctx).Where("id = ?", id).First(&user)
```

### ❌ 不要在事务外使用 tx

```go
// ❌ 不要在事务外使用事务连接
tx := repo.DB(ctx).Begin()
// ...

// ✅ 使用声明式事务（推荐）
svcgen.MyServiceCreateCallInfo.AddTag(agdb.TransactionTag, true)

// ✅ 或在持有 Repository 的层使用 Transaction() 管理事务边界
repo.Transaction(ctx, func(ctx context.Context) error {
    repo.DB(ctx).Create(&user)     // 自动使用事务连接
    return nil
})
```

> 注意：Biz 层注入的是 DAO 接口，不持有 `*gormdb.Repository`，因此无法使用 `repo.Transaction()`。biz 层应依赖声明式事务。

### ✅ 分页参数校验

```go
if pageNum < 1 || pageSize < 1 || pageSize > 100 {
    return nil, 0, errors.New("invalid pagination params")
}
```

### ✅ 命名 SQL 配合生成工具

命名 SQL 主要用于代码生成工具（`gen-go-db`），手动使用时优先选择 GORM 链式 API。仅在以下场景使用命名 SQL：
- 复杂的多表 JOIN 查询
- 数据库特定的 SQL 语法
- 需要精确控制 SQL 执行计划

## FAQ

**Q: 如何切换数据库驱动？**
A: 修改配置 `data.db.user.driver`，并确保对应驱动已通过 `RegisterDBOpener` 注册。默认支持 `mysql` / `ibmdb`，自定义驱动参考 [02-gormdb.md DBOpener 机制](02-gormdb.md#dbopener-驱动注册机制) 的 SQLite 示例。

**Q: 如何调试 SQL 日志？**
A: 设置 `data.db.logger.debug: true` 开启 Info 级别日志，会输出每条 SQL 及其耗时。

**Q: 声明式事务和手动事务可以混用吗？**
A: 声明式事务是推荐方式。如果确实需要手动事务（如批量操作），需要在注入 `*gormdb.Repository` 的层使用 `repo.Transaction()` — biz 层注入的是 DAO 接口，不适用此方式。采用传播行为（REQUIRED/SUPPORTS）进行嵌套控制。

**Q: 为什么 DB(ctx) 返回的事务连接是自动的？**
A: `TxContextAbility.GetTxFromCtx()` 检查 context 中是否绑定了 `*gorm.DB` 事务对象。如果当前在事务回调中，context 中有值，返回事务对象；否则返回普通 DB 连接。
