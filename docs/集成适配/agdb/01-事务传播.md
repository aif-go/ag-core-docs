# 事务传播

> 文件：`transaction.go` + `transaction_service_middleware.go`

Agdb 实现了一套类似 **Spring 事务传播** 的机制，支持 `REQUIRED` / `SUPPORTS` 两种传播行为，事务对象通过 Go `context.Context` 链式传递。

## 事务传播行为

```go
// transaction.go:22-33
type TransactionPropagation int

const (
    TRANSACTION_PROPAGATION_UNKNOWN  TransactionPropagation = iota // 未知: 非事务方式执行
    TRANSACTION_PROPAGATION_SUPPORTS                               // 支持: 有事务则加入，无事务则非事务方式执行
    TRANSACTION_PROPAGATION_REQUIRED                               // 必须: 有事务则加入，无事务则开启新事务
)
```

辅助判断函数：
```go
// transaction.go:35-37
func IsSupportsTransaction(tp TransactionPropagation) bool {
    return tp == TRANSACTION_PROPAGATION_SUPPORTS || tp == TRANSACTION_PROPAGATION_REQUIRED
}
```

> 代码中注释掉了更多传播行为（MANDATORY、REQUIRED_NEW、NOT_SUPPORTED、NEVER、NESTED），预留了扩展空间。

## TransactionManager 接口

```go
// transaction.go:39-43
type TransactionManager interface {
    Transaction(ctx context.Context, fn func(ctx context.Context) error) error
}
```

由 `gormdb.Repository` 实现。只暴露一个方法——开启事务并执行业务函数。

## TxContextAbility — 泛型事务上下文能力

```go
// transaction.go:46-65
type TxContextAbility[T any] struct{}

func (a *TxContextAbility[T]) BindTxToCtx(ctx context.Context, tx T) context.Context {
    rctx := context.WithValue(ctx, ctxTxKey{}, tx)
    return rctx
}

func (a *TxContextAbility[T]) GetTxFromCtx(ctx context.Context) T {
    tx := ctx.Value(ctxTxKey{})
    if tx == nil {
        ntx := *new(T)
        return ntx
    }
    return tx.(T)
}
```

关键设计：
- **泛型** `[T any]`：因为不同的 DB 框架事务类型不同，gorm 是 `*gorm.DB`，其他框架可能不同
- **私有 key** `ctxTxKey{}`：使用空结构体作为 context key，避免与其他 context 值冲突
- **零值安全**：context 中无事务时返回 `T` 的零值，而非 panic
- 该能力由 `TransactionManager` 实现者继承，业务代码**不直接使用**

## WithTransaction — 事务传播执行

```go
// transaction.go:68-85
func WithTransaction(
    ctx context.Context,
    tm TransactionManager,
    tp TransactionPropagation,
    fn func(ctx context.Context) error,
) error {
    switch tp {
    case TRANSACTION_PROPAGATION_UNKNOWN:
        return fn(ctx)          // 直接执行，不开启事务
    case TRANSACTION_PROPAGATION_SUPPORTS:
        return fn(ctx)          // 直接执行，不强制事务（调用方需自行判断）
    case TRANSACTION_PROPAGATION_REQUIRED:
        return doTransactionWithRequired(ctx, tm, fn)
    default:
        return fn(ctx)
    }
}
```

**REQUIRED 模式的核心逻辑**（`doTransactionWithRequired`，行 92-101）：

```
HasCurrentTx(ctx)?
    ├── true  → 复用当前事务，直接执行业务函数
    └── false → 调用 tm.Transaction() 开启新事务
```

```go
// transaction.go:92-101
func doTransactionWithRequired(ctx context.Context, tm TransactionManager, fn func(ctx context.Context) error) error {
    if HasCurrentTx(ctx) {
        return fn(ctx)
    } else {
        return tm.Transaction(ctx, func(ctx context.Context) error {
            return fn(ctx)
        })
    }
}
```

**HasCurrentTx** 判断 context 中是否存在事务对象：
```go
// transaction.go:88-90
func HasCurrentTx(ctx context.Context) bool {
    return ctx.Value(ctxTxKey{}) != nil
}
```

## 声明式事务中间件

通过 ag-service 的 **Middleware + PreOpt** 机制，在 service 方法上声明事务需求。

### TransactionPreOpt — 预处理器

```go
// transaction_service_middleware.go:19-46
func TransactionPreOpt(callInfo *ag_service.CallInfo) error {
    ttag := callInfo.GetTag(TransactionTag) // "transaction"
    if ttag == nil {
        return nil
    }
    // 解析 tag 值
    switch v := ttag.(type) {
    case bool:
        tp = TRANSACTION_PROPAGATION_REQUIRED  // 默认 REQUIRED
    case TransactionPropagation:
        tp = v                                  // 指定传播类型
    }
    // 将传播类型注册到 CallInfo
    callInfo.AddTag(transactionPropagationKey{}, tp)
}
```

**tag 含义**：
- `transaction: true` → 等同于 `REQUIRED`
- `transaction: 1` → 等同于 `REQUIRED`
- 不设 tag → 非事务方式执行

### TransactionMiddlewareProvider — 中间件

```go
// transaction_service_middleware.go:50-83
type TransactionMiddlewareProvider struct {
    tm TransactionManager
}

func (p *TransactionMiddlewareProvider) Condition(callInfo *ag_service.CallInfo) bool {
    return callInfo.HasTag(transactionPropagationKey{})
}

func (p *TransactionMiddlewareProvider) Middleware() ag_service.MiddlewareFunc {
    return func(next ag_service.Endpoint) ag_service.Endpoint {
        return func(ctx context.Context, req interface{}) (resp interface{}, rerr error) {
            // 从 CallInfo 获取事务传播类型
            tp := cinfo.GetTag(transactionPropagationKey{}).(TransactionPropagation)
            // 执行事务
            terr := WithTransaction(ctx, p.tm, tp, func(ctx context.Context) error {
                resp, rerr = next(ctx, req)
                return rerr
            })
            return resp, terr
        }
    }
}
```

**Condition** 方法判断当前调用是否需要拦截（有 `transactionPropagationKey` 标记）。

## 实现者：Repository

`gormdb.Repository` 实现了 `TransactionManager` 接口，并嵌入了 `TxContextAbility[*gorm.DB]`：

```go
// gormdb/repository.go:12-16
type Repository struct {
    agdb.TxContextAbility[*gorm.DB]
    db     *gorm.DB
    DbType string
}
```

事务实现：
```go
// gormdb/repository.go:55-61
func (r *Repository) Transaction(ctx context.Context, fn func(ctx context.Context) error) error {
    return r.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
        ctx = r.BindTxToCtx(ctx, tx)  // 将 *gorm.DB 绑定到 context
        return fn(ctx)
    })
}
```

**DB 获取**：优先返回 context 中的事务 DB，否则返回普通 DB：
```go
// gormdb/repository.go:44-52
func (r *Repository) DB(ctx context.Context) *gorm.DB {
    v := r.GetTxFromCtx(ctx)
    if v != nil {
        return v
    }
    return r.db.WithContext(ctx)
}
```

## 事务传播完整流程

```
Service 方法定义了 tag: "transaction"=true
    │
    ▼
TransactionPreOpt 解析 tag → 将 REQUIRED 注入 CallInfo
    │
    ▼
TransactionMiddlewareProvider.Condition() → true（有标记）
    │
    ▼
TransactionMiddlewareProvider.Middleware()
    │
    ├── HasCurrentTx(ctx)?
    │   ├── false → Repository.Transaction()
    │   │              ├── gorm.DB.Transaction()
    │   │              ├── BindTxToCtx(ctx, tx)  ← 事务绑定
    │   │              └── fn(ctx)  ← 业务代码通过 context 获取事务 DB
    │   │
    │   └── true → 直接执行 fn(ctx)（复用上层事务）
    │
    ▼
next(ctx, req) 执行实际业务逻辑
    │
    ▼
业务代码通过 Repository.DB(ctx) 获取 DB 实例
    ├── 有事务 → 返回事务 tx
    └── 无事务 → 返回普通 db
```

## 调用方视角

业务代码不需要直接调用 `WithTransaction`，只需在 service 方法上声明 tag，并通过 `Repository.DB(ctx)` 获取上下文感知的 DB 实例即可。详细见 [06-使用指南](06-使用指南.md)。
