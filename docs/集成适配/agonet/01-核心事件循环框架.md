# 核心事件循环框架

> 路径：`common/agonet/` | Engine + EventLoop + Conn 双缓冲 + Server/Client

## 架构分层

```
Server/Client.Start()
    │
    ▼
Engine.active()
    │
    ├── 创建 N 个 EventLoop（goroutine + chan any, 1024 缓冲）
    │
    ├── createListeners → listener.open() → net.Listen
    │     └── tlsIfNeed() → TLS/TLCP 包装
    │
    └── listenStream → Accept → 负载均衡 → EventLoop.ch
          │
          ▼
    goroutine.DefaultWorkerPool.Submit(readLoop)
          │
      for { tc.Read(buffer) → packTCPConn → el.ch }
```

### EventHandler

```go
// event_handler.go:4-19

    OnShutdown(eng Engine)
```

## EventLoop 事件循环

```go
// event_loop.go:17-26
type eventloop struct {

    idx          int                  // EventLoop 编号
    eng          *engine
    connCount    int32                // 活跃连接数
    connections  map[*conn]struct{}   // 连接集合
    eventHandler EventHandler
    goroutineId  int64                // goroutine ID（用于 InEventLoop 判断）
}
```

### run 主循环

```go
// event_loop.go:28-72
func (el *eventloop) run() (err error) {
    if el.eng.opts.LockOSThread {
        runtime.LockOSThread()
        defer runtime.UnlockOSThread()
    }

    for i := range el.ch {
        switch v := i.(type) {
        case error:          err = v                                     // 关闭信号
        case *netErr:        err = el.close(v.c, v.err)                  // 网络错误
        case *openConn:      err = el.open(v)                            // 新连接
        case *tcpConn:       err = el.read(unpackTCPConn(v))            // 数据到达
        case func() error:   err = v()                                   // 自定义任务
        }
        if errors.Is(err, aerrors.ErrEngineShutdown) { break }
    }
}
```

### open — 新连接处理

```go
// event_loop.go:74-91
func (el *eventloop) open(oc *openConn) error {
    c := oc.c
    el.connections[c] = struct{}{}
    out, action := el.eventHandler.OnOpen(c)
    if out != nil {
        c.rawConn.Write(out)  // 发送初始数据（如 HTTP 欢迎消息）
    }
    return el.handleAction(c, action)
}
```

### read — 数据读取与缓冲

```go
// event_loop.go:93-119
func (el *eventloop) read(c *conn) error {
    // 1. 调用 OnTraffic（业务处理）
    action := el.eventHandler.OnTraffic(c)

    // 2. 未消费的数据写入 inboundBuffer（弹性环形缓冲区）
    _, err := c.inboundBuffer.Write(c.buffer.B)
    c.buffer.Reset()
    return el.handleAction(c, action)
}
```

### wake — 手动唤醒

```go
// event_loop.go:121-127
func (el *eventloop) wake(c *conn) error {
    if _, ok := el.connections[c]; !ok { return nil }
    action := el.eventHandler.OnTraffic(c)
    return el.handleAction(c, action)
}
```

`Wake()` 用于业务代码主动触发 OnTraffic（如异步处理后需要继续读取）。

## Conn 双缓冲架构

连接的核心数据结构 `conn` 使用**两层缓冲**：

```go
// connection.go:32-44
type conn struct {
    ctx        any                         // 用户上下文
    loop       *eventloop
    buffer     *bytebufferpool.ByteBuffer  // 临时入站缓冲区（valyala/bytebufferpool）
    cache      []byte                      // Peek 缓存（byteslice 池）
    rawConn    net.Conn                    // 原始 TCP/TLS/TLCP 连接
    inboundBuffer elastic.RingBuffer       // 持久化入站缓冲区（elastic.RingBuffer）
}
```

### 双层缓冲策略

| 缓冲区 | 类型 | 用途 | 来源 | 归还 |
|--------|------|------|------|------|
| `buffer` | `bytebufferpool.ByteBuffer` | 临时存放本次 OnTraffic 收到的数据 | unpackTCPConn 写入 | OnTraffic 后 Reset |
| `inboundBuffer` | `elastic.RingBuffer` | 持久化 EventHandler 未消费的数据 | OnTraffic 后写入 | conn.release 时 Done |

### 数据流

```
OnTraffic 前:
  buffer → [本次 TCP 数据]
  inboundBuffer → [上次未处理的数据]

OnTraffic 中:
  c.Read(buf) / c.Next(n):
    1. 优先从 inboundBuffer 读
    2. inboundBuffer 读完 → 读 buffer
  
  c.Peek(n):
    1. 先窥视 inboundBuffer（可能返回两段数据 head+tail）
    2. 再窥视 buffer

  c.Discard(n):
    1. 优先丢弃 inboundBuffer
    2. 再丢弃 buffer

OnTraffic 后:
  inboundBuffer.Write(buffer.B) → 持久化未消费数据
  buffer.Reset() → 清空临时缓冲区
```

### Reader 接口方法

| 方法 | 行为 | 内存来源 |
|------|------|---------|
| `Read(p)` | 读取到 `p` 中 | inboundBuffer + buffer |
| `Next(n)` | 返回 n 字节并前进 | n ≤ 小 → 直接返回 buffer 切片；大 → byteslice.Get(n) |
| `Peek(n)` | 窥视 n 字节不前进 | inboundBuffer.Peek 返回两段；byteslice.Get 合并 |
| `Discard(n)` | 丢弃 n 字节并前进 | inboundBuffer.Discard + buffer 截断 |
| `InboundBuffered()` | 返回可用字节总数 | inboundBuffer.Buffered() + buffer.Len() |

### Writer 接口方法

| 方法 | 行为 | 并发安全 |
|------|------|---------|
| `Write(p)` | 同步写入 rawConn | ❌ 需在 EventLoop 中调用 |
| `AsyncWrite(buf, cb)` | 异步写入（通过 EventLoop.ch） | ✅ |
| `Flush()` | 空实现（无缓冲） | — |
| `ReadFrom(r)` | 从 io.Reader 拷贝到 rawConn | ❌ |

### conn.release — 资源释放

```go
// connection.go:372-392
func (c *conn) release() {
    c.rawConn = nil
    byteslice.Put(c.cache)       // 归还 Peek 缓存
    c.inboundBuffer.Done()       // 归还环形缓冲区到 ringbuffer.Pool
    bytebufferpool.Put(c.buffer) // 归还 ByteBuffer
}
```

## 连接生命周期

```
Client Dial / Server Accept
    │
    ▼
newStreamConn(el, nc, ctx)
    ├── bytebufferpool.Get()  → c.buffer
    ├── elastic.RingBuffer{}  → c.inboundBuffer（懒初始化）
    └── 设置 localAddr, remoteAddr
    │
    ▼
el.ch <- &openConn{c}
    │
    ▼
el.open(oc)
    ├── el.connections[c] = struct{}{}
    └── el.eventHandler.OnOpen(c)  ← 业务逻辑
    │
    ▼
El.ch <- &tcpConn{c, b} (多次)
    │
    ▼
el.read(unpackTCPConn(v))
    └── el.eventHandler.OnTraffic(c)  ← 业务逻辑
         └── inboundBuffer.Write(buffer.B)
    │
    ▼
el.ch <- &netErr{c, err} / closeFn
    │
    ▼
el.close(c, err)
    ├── el.eventHandler.OnClose(c, err)
    ├── c.rawConn.Close()
    └── c.release()  → 归还所有缓冲区
```

## 常见陷阱

### ❌ Handler 在 EventLoop goroutine 中阻塞

`OnBoot`、`OnOpen`、`OnTraffic`、`OnClose` 都在 EventLoop 的 goroutine 中同步执行。阻塞操作（数据库查询、HTTP 调用）会导致整个 EventLoop 停止处理其他连接的事件。

```go
// ❌ 在 OnTraffic 中同步调用外部服务
func (h *Handler) OnTraffic(c agonet.Conn) agonet.Action {
    resp := callExternalAPI(data) // 阻塞整个 EventLoop
    c.Write(resp)
    return agonet.None
}

// ✅ 用 EventLoop.Execute() 或 goroutine 异步处理
```

### ❌ 直接操作 `NetConn()`

`NetConn()` 返回底层 `net.Conn`，直接读写会绕过 agonet 的双缓冲机制，导致 `Next()`/`Peek()` 行为异常。

### ❌ 忘记调用 `Flush()`

`Write()` 是缓冲写入，数据可能留在缓冲区未发送。需要时调用 `Flush()` 确保数据实际发送。但 Simple 层的 `headHandler.HandleWrite` 直接调用 `Write1`（无缓冲），因此 Simple 管道层不需要手动 Flush。
