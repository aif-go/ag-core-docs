# 流式传输

> protobuf stream 方法：服务端实现、客户端调用、配置与限制

## 概述

AgKitex 支持 gRPC 三种流式模式。**默认的 `transportType: grpc` 已同时支持 unary 和 streaming**——对纯 gRPC 项目无需额外配置。流式方法的调用链路与普通 RPC 不同，**不走 ag-service proxy 中间件链**，需注意事务等功能对流式方法无效。

## TransportType 说明

Kitex 源码 `transport/keys.go` 中两个协议的定义：

```go
// GRPC  — 所有方法（含 unary 和 streaming）都走 gRPC 协议
GRPC Protocol = 1 << 3

// GRPCStreaming — 仅 streaming 方法走 gRPC 协议，unary 方法不受影响
// NOTE: only used in global config of the client side.
GRPCStreaming Protocol = 1 << 9
```

| 配置值 | unary 行为 | streaming 行为 | 适用场景 |
|---|---|---|---|
| `grpc`（默认） | gRPC 协议 | gRPC 协议 | 纯 gRPC 项目，**无需改配置** |
| `grpcstream` | 不变，保持自身默认 | gRPC 协议 | 混合协议（如 unary=TTHeader + streaming=gRPC） |

**结论：如果你的项目纯 gRPC，什么都不用改，默认 `grpc` 就能同时跑 unary 和 streaming。**

agkitex 客户端 `BuildSuite` 中将配置值映射到 Kitex 选项：

```go
switch config.TransportType {
case "grpc":
    opts = append(opts, client.WithTransportProtocol(transport.GRPC))
case "grpcstream":
    opts = append(opts, client.WithTransportProtocol(transport.GRPCStreaming))
default:
    opts = append(opts, client.WithTransportProtocol(transport.GRPC))
}
```

## Protobuf 定义

```protobuf
service StreamService {
    // 服务端流：客户端发一个请求，服务端持续返回
    rpc ServerStream(StreamRequest) returns (stream StreamResponse);

    // 客户端流：客户端持续发送，服务端返回一个响应
    rpc ClientStream(stream StreamRequest) returns (StreamResponse);

    // 双向流：双方独立读写
    rpc BidiStream(stream StreamRequest) returns (stream StreamResponse);
}
```

Kitex 代码生成：

```bash
kitex -service stream-service -module myapp idl/stream.proto
```

## 服务端实现

```go
type StreamServiceImpl struct{}

// 服务端流
func (s *StreamServiceImpl) ServerStream(
    req *StreamRequest,
    stream streamservice.StreamService_ServerStreamServer,
) error {
    for i := 0; i < 10; i++ {
        stream.Send(&StreamResponse{Data: fmt.Sprintf("msg-%d", i)})
    }
    return nil
}

// 客户端流
func (s *StreamServiceImpl) ClientStream(
    stream streamservice.StreamService_ClientStreamServer,
) error {
    var total int64
    for {
        req, err := stream.Recv()
        if err == io.EOF {
            return stream.SendAndClose(&StreamResponse{Data: fmt.Sprintf("total:%d", total)})
        }
        if err != nil {
            return err
        }
        total += req.Value
    }
}

// 双向流
func (s *StreamServiceImpl) BidiStream(
    stream streamservice.StreamService_BidiStreamServer,
) error {
    for {
        req, err := stream.Recv()
        if err == io.EOF {
            return nil
        }
        if err != nil {
            return err
        }
        stream.Send(&StreamResponse{Data: "echo:" + req.Data})
    }
}
```

注册方式与普通 RPC 相同：

```go
fx.Provide(
    akxserver.NewFxAgKitexServiceRegistry(func() *akxserver.AgKitexServiceRegistry {
        return akxserver.NewAgKitexServiceRegistry(
            streamservice.NewServiceInfo(),
            &StreamServiceImpl{},
        )
    }),
)
```

## 客户端调用

```go
type StreamClient struct {
    cli streamservice.Client
}

func NewStreamClient(suite *akxclient.KitexClientSuite) *StreamClient {
    return &StreamClient{
        cli: streamservice.NewClient("stream-service", client.WithSuite(suite)),
    }
}

// 服务端流：逐个接收
func (c *StreamClient) ServerStream(ctx context.Context, id int64) error {
    stream, err := c.cli.ServerStream(ctx, &StreamRequest{Id: id})
    if err != nil {
        return err
    }
    for {
        resp, err := stream.Recv()
        if err == io.EOF {
            break
        }
        if err != nil {
            return err
        }
        slog.Info("received", "data", resp.Data)
    }
    return nil
}

// 客户端流：逐个发送，最后接收响应
func (c *StreamClient) ClientStream(ctx context.Context, values []int64) (*StreamResponse, error) {
    stream, err := c.cli.ClientStream(ctx)
    if err != nil {
        return nil, err
    }
    for _, v := range values {
        stream.Send(&StreamRequest{Value: v})
    }
    return stream.CloseAndRecv()
}

// 双向流：独立收发
func (c *StreamClient) BidiStream(ctx context.Context) error {
    stream, err := c.cli.BidiStream(ctx)
    if err != nil {
        return err
    }
    // 发送
    go func() {
        for i := 0; i < 5; i++ {
            stream.Send(&StreamRequest{Data: fmt.Sprintf("msg-%d", i)})
        }
        stream.Close()
    }()
    // 接收
    for {
        resp, err := stream.Recv()
        if err == io.EOF {
            break
        }
        if err != nil {
            return err
        }
        slog.Info("received", "data", resp.Data)
    }
    return nil
}
```

## 与普通 RPC 的关键区别

流式方法不走 `Endpoint` 函数签名 `func(ctx, req) (resp, err)`，ag-service proxy 对其**直接透传**：

```
普通 RPC：
   请求 → ag-service proxy → 中间件链(事务/日志/...) → 业务实现 → 响应

流式 RPC：
   请求 → ag-service proxy → （跳过中间件链）→ 业务实现 → stream
```

**因此以下功能对流式方法无效：**

- 声明式事务 (`svcgen.XxxCallInfo.AddTag(agdb.TransactionTag, true)`)
- ag-service 全局中间件（日志、鉴权等）
- CallInfo 增强（`CallInfoOpt`）

流式方法内如需事务，需在业务实现中手动管理。
