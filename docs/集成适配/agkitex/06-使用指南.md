# AgKitex 使用指南

> 面向业务开发者：快速上手、配置、服务端/客户端开发、最佳实践

---

## 快速开始

### 1. 添加依赖

```go
require (
    github.com/aif-go/ag-core latest
    github.com/cloudwego/kitex latest
    github.com/kitex-contrib/registry-nacos  // Nacos 注册
    github.com/kitex-contrib/registry-nacos/resolver  // Nacos 发现
)
```

### 2. 注册 FX 模块

```go
import (
    "github.com/aif-go/ag-core/fxs"
    akxserver "github.com/aif-go/ag-core/contribute/agkitex/server"
)

func main() {
    app := fxs.FxAppMode(
        // 基础模块
        fxs.FxAgConfModule,
        fxs.FxAgSlogModule,

        // Kitex Server
        akxserver.FxKitexServerBaseModule,

        // 注册 RPC 服务
        fx.Provide(
            akxserver.NewFxAgKitexServiceRegistry(func() *akxserver.AgKitexServiceRegistry {
                return akxserver.NewAgKitexServiceRegistry(
                    myservice.NewServiceInfo(),  // proto 生成的 ServiceInfo
                    &MyServiceImpl{},            // 业务实现
                )
            }),
        ),
    )
    app.Run()
}
```

## 配置

### Server 配置

```yaml
kitex:
  server:
    host: 0.0.0.0              # 绑定 Host
    port: 7000                  # 绑定端口
    adaptivePort: false         # 自适应端口
    serviceName: my-service     # 服务名
    enableIPRange: ""           # IP 范围（注册用）

    grpc:
      enable: true              # 启用 gRPC 协议（默认）
      maxConnectionIdle: 0      # 最大空闲连接时间（秒）

    registry:                   # Nacos 注册
      cluster: DEFAULT
      group: DEFAULT_GROUP
```

### Client 配置

```yaml
kitex:
  client:
    rpcTimeout: 30              # RPC 超时（秒）
    transportType: grpc         # grpc（默认，支持 unary+streaming）| grpcstream（混合协议场景）

    resolver:
      enabled: true             # 启用服务发现
      type: agnacos             # agnacos（自定义）| nacos（官方）
      nacos:
        group: DEFAULT_GROUP
        cluster: DEFAULT

    conn:
      grpcConnPoolSize: 12      # gRPC 连接池大小（默认 GOMAXPROCS * 1.5）
```

## 服务端开发

### 1. 定义 Protobuf Service

```protobuf
service MyService {
    rpc GetUser (GetUserRequest) returns (GetUserResponse);
}
```

生成 Kitex 代码：
```bash
kitex -service my-service -module myapp idl/myservice.proto
```

### 2. 实现业务 Handler

```go
type MyServiceImpl struct{}

func (s *MyServiceImpl) GetUser(ctx context.Context, req *GetUserRequest) (*GetUserResponse, error) {
    user, err := userRepo.FindByID(ctx, req.UserId)
    if err != nil {
        return nil, err
    }
    return &GetUserResponse{User: user}, nil
}
```

### 3. 注册服务

```go
fx.Provide(
    akxserver.NewFxAgKitexServiceRegistry(func() *akxserver.AgKitexServiceRegistry {
        return akxserver.NewAgKitexServiceRegistry(
            myservice.NewServiceInfo(),
            &MyServiceImpl{},
            // server.WithOption(...)  // 可选注册选项
        )
    }),
)
```

### 4. 实现流式 Handler

> 注册方式与普通 RPC 完全相同。流式 Handler 签名不同，且**不走 ag-service proxy 中间件链**。详见 [07-流式传输](07-流式传输.md)。

**Proto 定义：**

```protobuf
service MyService {
    rpc Subscribe(SubscribeRequest) returns (stream Event);  // 服务端流
}
```

**Handler 实现：**

```go
func (s *MyServiceImpl) Subscribe(
    req *SubscribeRequest,
    stream myservice.MyService_SubscribeServer,
) error {
    for {
        event, err := fetchEvent(req.Topic)
        if err != nil {
            return err
        }
        if err := stream.Send(event); err != nil {
            return err
        }
        time.Sleep(time.Second)
    }
}
```

**注册到 FX（与普通 RPC 完全一致）：**

```go
akxserver.NewFxAgKitexServiceRegistry(func() *akxserver.AgKitexServiceRegistry {
    return akxserver.NewAgKitexServiceRegistry(
        myservice.NewServiceInfo(),
        &MyServiceImpl{},
    )
})
```

> ⚠️ 流式方法绕过 ag-service 中间件链，全局中间件（鉴权、日志 Hook 等）**对流式 RPC 无效**。如需事务，手动注入 `*gormdb.Repository` 调用其 `Transaction()` 方法。

### 5. 注册自定义中间件

```go
// 普通中间件
fx.Provide(
    akxserver.NewFxServerMiddlewareProvider(func() endpoint.Middleware {
        return func(next endpoint.Endpoint) endpoint.Endpoint {
            return func(ctx context.Context, req, resp interface{}) error {
                start := time.Now()
                err := next(ctx, req, resp)
                slog.Info("rpc", "elapsed", time.Since(start), "err", err)
                return err
            }
        }
    }),
)

// 带优先级的中间件
fx.Provide(
    akxserver.NewFxServerPrioritizedMiddlewareProvider(func() server.PrioritizedServerMiddleware {
        return &server.SimplePrioritizedServerMiddleware{
            Order:      server.ServerMiddlewarePriorityHigh,
            Middleware: myMiddleware,
        }
    }),
)
```

## 客户端开发

### 1. 创建 RPC Client

```go
import akxclient "github.com/aif-go/ag-core/contribute/agkitex/client"

type MyService struct {
    cli myservice.Client
}

func NewMyService(suite *akxclient.KitexClientSuite) *MyService {
    cli := myservice.NewClient("my-service", client.WithSuite(suite))
    return &MyService{cli: cli}
}
```

### 2. 发起 RPC 调用

```go
func (s *MyService) GetUser(ctx context.Context, userID int64) (*User, error) {
    resp, err := s.cli.GetUser(ctx, &GetUserRequest{UserId: userID})
    if err != nil {
        return nil, err
    }
    return resp.User, nil
}
```

### 3. 流式调用

> Client 创建方式与普通 RPC 完全相同。详见 [07-流式传输](07-流式传输.md)。

```go
func (s *MyService) Subscribe(ctx context.Context, topic string) error {
    stream, err := s.cli.Subscribe(ctx, &SubscribeRequest{Topic: topic})
    if err != nil {
        return err
    }
    for {
        event, err := stream.Recv()
        if err == io.EOF {
            return nil
        }
        if err != nil {
            return err
        }
        handleEvent(event)
    }
}
```

三种流式模式（服务端流 / 客户端流 / 双向流）的完整示例见 [07-流式传输](07-流式传输.md)。

## 最佳实践

### ✅ 使用 `agnacos` 作为 Resolver 类型

如果你的服务需要与 Spring gRPC 项目互通，必须使用 `type: agnacos`。它能够正确解析 Spring 服务注册时写入的 `gRPC_port` metadata。

### ✅ 通过 ServiceRegistry 注册服务

不要直接调用 `server.RegisterService()`，而是通过 `AgKitexServiceRegistry` + FX group 注入，由框架统一管理注册。

### ✅ 使用优先级中间件

```go
const (
    // 日志/监控
    MyLogging = ServerMiddlewarePriorityHighest    // 0
    // 鉴权
    MyAuth    = ServerMiddlewarePriorityHigh       // 1000
    // 业务逻辑
    MyBiz     = ServerMiddlewarePriorityNormal     // 2000
    // 兜底
    MyFallback = ServerMiddlewarePriorityLow       // 3000
)
```

### ✅ 传递 context

始终将 `ctx` 作为第一个参数传递，确保元数据透传、超时控制、日志上下文正常工作。

### ❌ 不要混用 Resolver 类型

```go
// ❌ Spring gRPC 服务使用 nacos 官方 Resolver
// → 连接端口错误（gRPC_port metadata 不会被解析）

// ✅ 使用 agnacos（自定义 Resolver）
config.Resolver.Type = "agnacos"
```

### ❌ 不要手动管理 Kitex Server

```go
// ❌ 手动创建
svr := server.NewServer()
svr.RegisterService(...)
svr.Run()

// ✅ 通过 FX 模块自动装配
akxserver.FxKitexServerBaseModule
```

## FAQ

**Q: 如何选择 `agnacos` 和 `nacos` 两种 Resolver？**
A: 连接纯 Kitex 服务用 `nacos`；连接 Spring gRPC 或其他非 Kitex 服务用 `agnacos`（兼容 `gRPC_port` metadata）。

**Q: 如何配置多服务注册？**
A: 多个 `AgKitexServiceRegistry` 通过 FX group 注入，Holder 会自动依次注册：
```go
fx.Provide(
    NewFxAgKitexServiceRegistry(func() *AgKitexServiceRegistry { return reg1 }),
    NewFxAgKitexServiceRegistry(func() *AgKitexServiceRegistry { return reg2 }),
)
```

**Q: 如何启用 gRPC 流式传输？**
A: 无需额外配置。默认的 `transportType: grpc` 已同时支持 unary 和 streaming。`grpcstream` 仅用于混合协议场景（如 unary=TTHeader + streaming=gRPC）。详见 [07-流式传输](07-流式传输.md)。

**Q: 如何配置连接池？**
A: 设置 `conn.grpcConnPoolSize`，默认值为 `GOMAXPROCS * 1.5`。
