# AgNacos 使用指南

> 面向部署/运维：配置、FX 模块注册、验证

---

## 快速开始

在 `main` 中注册 FX 模块：

```go
import (
    "github.com/aif-go/ag-core/fxs"
    "github.com/aif-go/ag-core/contribute/agnacos"
)

func main() {
    app := fxs.FxAppMode(
        fxs.FxAgConfModule,                       // 配置系统（必须先注册）

        agnacos.FxNacosConfigMode,                 // ① 配置中心客户端
        agnacos.FxEnableNacosRemoteConfigMode,     // ② 启用远程配置注入
        agnacos.FxNacosNamingMode,                 // ③ 服务发现客户端
    )
    app.Run()
}
```

三个 FX 模块按需启用：

| 模块 | 作用 | 何时启用 |
|------|------|---------|
| `FxNacosConfigMode` | 创建 ConfigClient | 需要从 Nacos 拉取配置 |
| `FxEnableNacosRemoteConfigMode` | 将远程配置注入 ag_conf | 配合 ① 使用，单独无效 |
| `FxNacosNamingMode` | 创建 NamingClient | 需要使用 Nacos 服务发现/注册 |

> 只做服务发现不需要配置中心：只注册 `FxNacosNamingMode`。

## 配置

### 配置中心

配置前缀：`nacos.config`

```yaml
nacos:
  config:
    # ── 开关 ──
    enable: true                  # 默认 true

    # ── 连接（SCProperties）──
    serveraddr: 192.168.1.1:8848,192.168.1.2:8848   # Nacos 地址，逗号分隔，必填
    namespace: aic-dev            # 命名空间 ID
    username: nacos               # 用户名
    password: nacos               # 密码
    schema: http                  # 协议，默认 http
    contextpath: /nacos           # 上下文路径，默认 /nacos
    loglevel: error               # SDK 日志级别，默认 error

    # ── 远程配置 DataID 列表 ──
    dataids:                      # 对应 Go 字段 DataIDs（大小写不敏感）
      - dataid: app-config.yaml   # 配置 ID，必填
        group: DEFAULT_GROUP      # 分组，默认 DEFAULT_GROUP
        type: yaml                # 格式，默认 yaml（支持 yaml/properties/json）
        autorefresh: true         # 是否监听变更，默认 true
      - dataid: db-config.yaml
        group: DEFAULT_GROUP
        type: yaml
        autorefresh: true
```

### 服务发现

配置前缀：`nacos.naming`

```yaml
nacos:
  naming:
    enable: true                  # 默认 true
    serveraddr: 192.168.1.1:8848  # Nacos 地址，必填
    namespace: aic-dev
    username: nacos
    password: nacos
    schema: http                  # 默认 http
    contextpath: /nacos           # 默认 /nacos
    loglevel: error               # 默认 error
```

### 同时启用两者

config 和 naming 的 `SCProperties` 连接信息**各自独立配置**。推荐通过 `${...}` 占位符引用复用，避免重复：

```yaml
nacos:
  config:
    enable: true
    serveraddr: 192.168.1.1:8848
    namespace: aic-dev
    username: nacos
    password: nacos
    dataids:
      - dataid: app-config.yaml
        group: DEFAULT_GROUP
        type: yaml
        autorefresh: true

  naming:
    enable: true
    serveraddr: ${nacos.config.serveraddr}   # ← 引用 config 的值
    namespace: ${nacos.config.namespace}
    username: ${nacos.config.username}
    password: ${nacos.config.password}
```

占位符语法 `${key}` 由 ag_conf 的 `resolveNestedPlaceholders` 支持，可在任意属性值中使用。

## 配置键名规则

配置 YAML 中的 key 必须与 Go 结构体字段名**拼写一致**（大小写不敏感）：

| YAML 键 | Go 字段 | 是否绑定 |
|---------|---------|---------|
| `dataids` | `DataIDs` | ✅ EqualFold 匹配 |
| `serveraddr` | `ServerAddr` | ✅ |
| `namespace` | `NameSpace` | ✅ |
| `autorefresh` | `AutoRefresh` | ✅ |
| `dataidlist` | 无 | ❌ 拼写不匹配 |

## 验证

### 配置中心

启动日志关键字：

```
# 已启用
"nacos config"                       → 每个 DataID 加载成功

# 已禁用 / 无配置
"nacos remote config is disable"     → Enable=false
"nacos remote config dataids is empty" → DataIDs 为空
"nacos config is empty"              → DataID 在 Nacos 上无内容（不阻断）
```

### 服务发现

启动日志关键字：

```
"create kitex nacos registry"        → Kitex 服务注册成功（agkitex 端输出）
```

Nacos 控制台验证：
- **服务列表** → 查看 `kitex.server.registry` 中 `group` 对应分组下的服务实例
- **配置列表** → 查看 `dataids` 中每个 DataID 的内容

## FAQ

**Q: `serveraddr` 可以配多个地址吗？**

A: 可以，逗号分隔。不写端口默认 8848。

```yaml
serveraddr: 192.168.1.1:8848,192.168.1.2:8848,10.0.0.1
#                                            ↑ 默认端口 8848
```

**Q: 配置中心拉取失败会阻断启动吗？**

A: 会。`GetConfig` 失败返回 error，启动中止。但 DataID 内容为空（`content == ""`）不会阻断，仅打印日志跳过。

**Q: 远程配置修改后多久生效？**

A: 实时。`AutoRefresh=true` 时通过 `ListenConfig` 监听变更，回调触发后会重建 PropertySource 并替换到 ag_conf 配置链中。

**Q: 远程配置的优先级是什么？**

A: **-D 命令行 > 系统环境变量 > Nacos 远程配置 > 本地文件**。`AddFirst(环境变量)` → `AddBefore(-D)` → `AddAfter(环境变量, Nacos)` → `AddLast(本地)`。

**Q: config 和 naming 的连接地址必须一致吗？**

A: 不强制，但通常一致。它们是独立的两个 `SCProperties` 实例，分别从 `nacos.config.*` 和 `nacos.naming.*` 绑定。推荐用 `${nacos.config.serveraddr}` 占位符复用，避免写两遍。

**Q: 配置中的加密值怎么处理？**

A: 以 `{cipher}` 为前缀的值会自动解密。例如 `password: "{cipher}xxxxx"` 会在注入 PropertySource 后调用 `CreateOrUpdateDecryptForPropertySource` 解密。
