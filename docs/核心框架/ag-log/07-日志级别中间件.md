# AgLog 日志级别中间件

> 自 `746c275` 引入 | 文件：`agslog/agslog_level_mw.go`

## 作用

按 handler 名称精细控制日志级别。不依赖第三方 `slog-multi` pipe 机制，纯 `slog.Handler` 包装实现。

## 配置

```yaml
aglog:
  level:
    root: "error"                    # 全局默认级别
    handlers:
      zap1: "warn"                   # 指定 handler 的级别
      asynclog1: "info"
```

## 优先级

```
handler 专属级别 > 全局 root 级别 > slog.Handler 自身级别
```

即：
1. 如果 `level.handlers` 中指定了该 handler → 使用指定级别
2. 如果未指定但在 `level.root` 设了值 → 使用 root 级别
3. 如果都未设置 → 走 handler 本身的 `log_level`（和原来一样）

## 实现原理

- 在 `slog_wrap_config.go` 的 Builder 构造流程中，中间件在 handler 创建后、注册前包装
- `LevelMwConfigHelper` 解析 YAML 配置，构建 handler → level 的映射
- `NewLevelMiddleware` 创建 `Middleware` 实例，重写 `Handle()` 方法，在调用下层 handler 前判断日志级别
- 使用 `singleflight.Group` 缓存级别查找结果，避免重复解析

## 使用示例

```yaml
aglog:
  isDefault: false
  level:
    root: "warn"                     # 全局只在 warn 及以上输出
    handlers:
      debug_logger: "debug"          # 但 debug_logger 仍输出 debug 级别
  zap:
    logs:
      app_logger:
        log_level: debug
        console: true
      debug_logger:
        log_level: debug
        log_file_name: /tmp/debug.log
```

此配置下：
- `app_logger` → `warn`（受 root 限制）
- `debug_logger` → `debug`（专属配置覆盖 root）

## 注意事项

- 此中间件只影响**日志输出**，不影响 handler 自身的资源消耗（如文件句柄依然打开）
- 中间件是**非侵入式**的，不修改 handler 的 `Enabled()` 行为，只在 `Handle()` 时过滤
