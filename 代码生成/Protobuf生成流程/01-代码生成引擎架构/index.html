    代码生成引擎架构¶

    路径：tool/aggen/ | 从 proto 解析到 Go 代码生成的核心引擎

    概述¶

    aggen 是 ag-core 代码生成的核心引擎，位于 tool/aggen/ 目录下。它被 6 个 protoc 插件调用（protoc-gen-go-agg*），每个插件只负责调用解析和特定目标的生成器：

    ┌─────────────────────────────────────────────────────────────┐
│                    aggo proto 命令                           │
│  protoc 包装器：选择插件 + 构造参数 + 调用 protoc           │
└──────────┬──────────────────────────────────────┬──────────┘
           │                                      │
           ▼                                      ▼
    ┌──────────┐                          ┌──────────────┐
    │ protoc   │  protoc 标准插件          │ protoc-gen-* │
    │ -gen-go  │  → *.pb.go               │ agcore 插件族 │
    └──────────┘                          └──────┬───────┘
                                                  │
                    ┌─────────────────────────────┐
                    │       aggen 引擎             │
                    │                             │
                    │  ┌─────────────────────┐    │
                    │  │ protoc.Parse(gen,f) │    │  ← 解析
                    │  └──────────┬──────────┘    │
                    │             ▼               │
                    │  ┌─────────────────────┐    │
                    │  │   GennerInfo         │    │  ← 数据载体
                    │  │   (GlobalInfo →      │    │
                    │  │    PackageGroups →    │    │
                    │  │     PackageInfos →    │    │
                    │  │      Services →       │    │
                    │  │       Methods)        │    │
                    │  └──────────┬──────────┘    │
                    │             ▼               │
                    │  ┌─────────────────────┐    │
                    │  │  generator.GenRender │   │  ← 生成
                    │  │  4 级 Scope 遍历     │    │
                    │  │  → TaskGenFunc       │    │
                    │  │  → Task.Render       │    │
                    │  │  → doWriteFile       │    │
                    │  └─────────────────────┘    │
                    └─────────────────────────────┘

    一、类型系统（types/）¶

    1.1 信息树¶

    protobuf 文件的结构被解析为四层信息树，每层对应不同的 Scope（作用域）：

    GlobalInfo
  ├── ModuleInfo          模块信息（go.mod 名称 + 路径）
  └── PackageGroups       包组表 key: PkgName
        └── PackageGroup
              ├── PkgInfo             包信息（PkgName, ImportPath, PkgRefName）
              └── PackageInfos[]       每个 proto 文件对应一个
                    └── PackageInfo
                          ├── IDLName           proto 文件路径
                          ├── Services[]
                          │     └── ServiceInfo
                          │           ├── ServiceName     "UserService"
                          │           ├── RawServiceName  "user_service"
                          │           ├── Methods[]
                          │           │     └── MethodInfo
                          │           │           ├── Name      "CreateUser"
                          │           │           ├── RawName   "create_user"
                          │           │           ├── Args[]      → Parameter
                          │           │           ├── Resp        → Parameter
                          │           │           ├── HttpDescs[] → MethodHttpDesc
                          │           │           └── ClientStreaming / ServerStreaming
                          │           └── HasStreaming
                          └── ModuleInfo

    1.2 核心结构体¶

    PkgInfo — 包元信息，贯穿整个类型体系：

    // types/type.go:6-11
type PkgInfo struct {
    PkgName    string // PROTO: package，如 "api.student"
    ImportPkg  string // PkgName 中 "." 替换为 "/"，如 "api/student"
    PkgRefName string // path.Base(go_package)，如 "student"
    ImportPath string // go_package 原始值，如 "xxx/api/student"
}
    字段 来源 示例
    PkgName proto 文件 package 声明 api.student
    ImportPkg PkgName 转换 api/student
    PkgRefName go_package 的基名 student
    ImportPath go_package 原值 gitlab.com/xxx/api/student

    PackageGroup — 包组：一个 proto package 对应一个 Group，多个 proto 文件可以在同一个 package 下：

    // types/type_module.go:18-23
type PackageGroup struct {
    PkgInfo      PkgInfo        // 约束：同组内 PkgName 和 ImportPath 必须相同
    PackageInfos []*PackageInfo // 每个 proto 文件一个
    ModuleInfo   *ModuleInfo
}

    ServiceInfo — 服务信息：

    // types/type_service.go:4-34
type ServiceInfo struct {
    PkgInfo
    ServiceName      string   // Go 命名，如 "UserService"
    RawServiceName   string   // proto 原始定义，如 "user_service"
    ServiceTypeName  func() string  // 返回 PkgRefName + "." + ServiceName
    Methods          []*MethodInfo
    HasStreaming     bool
    GenerateHandler  bool
    Deprected        bool
    Comment          CommentSet
}

    MethodInfo — 方法信息：

    // types/type_method.go:4-29
type MethodInfo struct {
    PkgInfo
    ServiceName        string
    Name               string   // Go 命名，"CreateUser"
    RawName            string   // proto 原始，"create_user"
    Args               []*Parameter  // 当前只支持 1 个参数
    Resp               *Parameter
    ArgStructName      string   // Name + "Args"
    ResStructName      string   // Name + "Result"
    ClientStreaming    bool
    ServerStreaming    bool
    IsStreaming        bool
    HttpDescs          []*MethodHttpDesc
    Deprected          bool
    Comment            CommentSet
}

    MethodHttpDesc — HTTP 注解（来自 google.api.http 的 option）：

    // types/type_http.go:3-20
type MethodHttpDesc struct {
    Name         string     // 方法名
    OriginalName string     // 原始方法名
    Num          int        // 同名函数序号（多 HTTP 绑定）
    Request      string     // 入参类型名
    Reply        string     // 响应类型名
    Path         string     // URL 路径，如 /v1/student/{id}
    Method       string     // GET / POST / PUT / DELETE / PATCH
    HasVars      bool       // 是否有路径参数
    PathVars     []string   // 路径参数列表
    HasBody      bool       // 是否有 body
    Body         string     // body 字段名（* 表示整个请求对象）
    ResponseBody string     // 响应 body
}

    1.3 GennerInfo — 模板渲染数据载体¶

    GennerInfo 是传递给 Go text/template 的数据对象。它包含不变的基础数据（GlobalInfo）和逐层缓存（随 Scope 级别变化）：

    // types/type_gen.go:9-28
type GennerInfo struct {
    // 不变
    pluginName   string              // 当前插件名
    Versions     map[string]string   // 版本信息
    ModuleInfo   *ModuleInfo         // go.mod 信息
    GlobalInfo   *GlobalInfo         // 全局信息树

    // 缓存（随 Scope 遍历变化）
    PkgInfo       *PkgInfo
    PackageGroup  *PackageGroup
    PackageInfo   *PackageInfo
    ServiceInfo   *ServiceInfo
    Imports       map[string]map[string]bool  // import path → alias
    Source        []string                    // 源文件列表
    GenPkgRefName string                      // 生成目录的包名
    GenScope      string                      // 当前生成级别
}

    渲染前调用 Reset() 清空缓存，然后 SetVersion()、AddSource() 填充当前层级的上下文。

    二、Proto 解析（parser/protoc/）¶

    2.1 入口：Parse()¶

    // parser/protoc/plugin.go:25-67
func Parse(gen *protogen.Plugin, files []*protogen.File) (*types.GennerInfo, error)
    1. 调用 util.GetPwdModInfo() 获取当前模块信息（go.mod 解析）
    2. 创建空的 GlobalInfo
    3. 遍历每个 proto 文件 → parseFile()
    4. 包装为 GennerInfo，注入 protoc 版本

    2.2 文件解析链¶

    parseFile(ctx, gen, globalInfo, f)
    │
    └── parsePackageInfo(ctx, f)
          │
          ├── f.Desc.Path()           → PackageInfo.IDLName
          ├── f.GoImportPath          → PkgInfo.ImportPath
          ├── f.Proto.GetPackage()    → PkgInfo.PkgName
          ├── path.Base(ImportPath)   → PkgInfo.PkgRefName (goSanitized)
          │
          ├── 遍历 f.Services
          │     └── parseServiceInfo(ctx, s)
          │           ├── s.GoName          → ServiceInfo.ServiceName
          │           ├── s.Desc.Name()     → ServiceInfo.RawServiceName
          │           └── 遍历 s.Methods
          │                 └── parseMethodInfo(ctx, m)
          │                       ├── m.GoName       → MethodInfo.Name
          │                       ├── m.Desc.Name()  → MethodInfo.RawName
          │                       ├── convertParameter(m.Input, "Req")  → Args
          │                       ├── convertParameter(m.Output, "Resp") → Resp
          │                       ├── parserMethodHttpDesc(m)            → HttpDescs
          │                       └── m.Desc.IsStreamingClient/Server    → Stream 标志
          │
          └── globalInfo.AddPackageInfo(pkg)  → 归入 PackageGroup
                └── 约束检查：同 PkgName 的 ImportPath 必须一致

    2.3 Protobuf 属性到内部类型的映射¶

    Protobuf 属性 内部类型字段 用途
    file.Desc.Path() PackageInfo.IDLName 源文件路径，模板中标记代码来源
    file.GoImportPath PkgInfo.ImportPath Go import 路径
    path.Base(ImportPath) PkgInfo.PkgRefName 包引用名（目录名、import 别名）
    file.Proto.GetPackage() PkgInfo.PkgName proto 包名（"api.student"）
    service.GoName ServiceInfo.ServiceName Go 命名服务名（"UserService"）
    service.Desc.Name() ServiceInfo.RawServiceName proto 原始服务名
    method.GoName MethodInfo.Name Go 命名方法名（"CreateUser"）
    method.Desc.Name() MethodInfo.RawName proto 原始方法名
    method.Input.GoIdent Parameter.Deps, .Type, .RawType 请求参数类型 + 依赖
    method.Output.GoIdent Parameter.Deps, .Type, .RawType 响应参数类型 + 依赖
    proto.GetExtension(httpRule) MethodHttpDesc.* HTTP 方法 + 路径 + Body

    2.4 HTTP 注解解析¶

    parser_http.go 解析 google.api.http option。支持：

    • 标准方法：GET / POST / PUT / DELETE / PATCH
    • 路径变量：/v1/student/{id} 提取到 PathVars
    • Body 映射：body: "*"（整个请求对象）或 body: "field_name"
    • ResponseBody：响应中只返回某字段
    • 额外绑定：AdditionalBindings 支持同一方法多 HTTP 规则

    三、代码生成（generator/）¶

    3.1 四层 Scope 遍历¶

    GenRender 是生成器的核心入口，按 Scope 从大到小逐层遍历：

    GenRender(geni, taskGens)
    │
    ├── 1. ScopeModule                    全局级别
    │     geni.GenScope = "module"
    │     geni.AddSource(所有文件)
    │     → doGenRender(taskGens, geni, ScopeModule)
    │
    ├── 2. ScopePackageGroup              包组级别（同 package 的 proto 文件）
    │     geni.GenScope = "package_group"
    │     geni.PkgInfo / geni.PackageGroup 已设置
    │     geni.AddSource(同组所有文件)
    │     → doGenRender(taskGens, geni, ScopePackageGroup)
    │
    ├── 3. ScopePackage                   Proto 文件级别
    │     geni.GenScope = "package"
    │     geni.PackageInfo 已设置
    │     geni.AddSource(单文件)
    │     → doGenRender(taskGens, geni, ScopePackage)
    │
    └── 4. ScopeService                   服务级别（每个 Service 一个循环）
          geni.GenScope = "service"
          geni.ServiceInfo 已设置
          → doGenRender(taskGens, geni, ScopeService)

    ScopeModule         ── 生成：zfx_adapter.go, zfx_adapter_init.go, zfx_service.go
    │
ScopePackageGroup   ── 生成：agserver_*_interface.go, zfx_agservice_proxy_*.go
    │
ScopePackage        ── 当前无使用（预留）
    │
ScopeService        ── 生成：agkitex_*_server.go, aghertz_*_server.go,
                       agservice_*.go, agservice_*_proxy.go 等

    3.2 Task 系统¶

    每个生成器注册 TaskGenFunc 到 TaskGenerators，返回 []*types.Task。每个 Task 定义一个输出文件：

    // types/task.go:46-58
type Task struct {
    Name      string                      // 文件名
    Path      string                      // 文件路径（含文件名）
    Text      string                      // Go text/template 模板文本
    SetImport func(*GennerInfo) error     // 设置 import 的回调
    IsSkip    func(*GennerInfo) bool      // 跳过判断

    *template.Template                    // 编译后的模板
    Scope      ScopeType                  // 所属 Scope
    OutputType OutputType                 // 输出策略
}

    输出策略：

    类型 行为
    OutputTypeOverride（默认） 覆盖写入
    OutputTypeNotOverride 文件已存在则跳过（业务模板使用）
    OutputTypeAppend 未实现
    OutputTypeInsert 未实现

    3.3 渲染与写入¶

    Task.Render(geni)
    │
    ├── Task.Build()          → 编译 text/template
    ├── t.ExecuteTemplate()   → 渲染（模板数据 = GennerInfo）
    └── 返回 *types.File{Name, Content, OutputType}
          │
          ▼
doWriteFile(fs)
    ├── fscheck()             → 检查文件重复覆盖
    └── tryWriteFile(f)       → 根据 OutputType 策略写入
          └── writeFile()
                ├── .go 文件 → go/format.Source 格式化
                └── os.WriteFile 写入

    四、文件路径与命名规则¶

    4.1 路径计算原则¶

    所有输出路径由每个 Task 的 TaskGenFunc 在生成时动态计算。路径基于 proto 文件的三个属性：

    1. PkgRefName — 包的引用名，决定 api/ 或 internal/ 下的中间目录
    2. ServiceName（小写化） — 服务名的小写形式，决定适配层子目录
    3. PluginName — 插件名，决定前缀（agkitex_、aghertz_ 等）

    4.2 各插件文件生成路径表¶

    插件 Scope 文件 路径
    go package {pkg}.pb.go api/{PkgRefName}/{pkg}.pb.go
    api package_group agserver_{PkgRefName}_interface.go api/{PkgRefName}/agserver_{PkgRefName}_interface.go
    server module zfx_adapter.go internal/adpgen/zfx_adapter.go
    module zfx_adapter_init.go internal/adpgen/adpinit/zfx_adapter_init.go
    kitex (server) service agkitex_{svcLower}_server.go internal/adpgen/kitex/{svcLower}/
    service agkitex_{svcLower}_fx.go 同上
    service zfx_agkitex_{PkgRefName}_{svcLower}_adpinit.go internal/adpgen/adpinit/
    kitex (client) service agkitex_{svcLower}.go internal/adpgen/kitex/{svcLower}/
    service agkitex_{svcLower}_client.go 同上
    service agkitex_{svcLower}_agclient.go 同上
    hertz (server) service aghertz_{svcLower}_server.go internal/adpgen/hertz/{svcLower}/
    service aghertz_{svcLower}_fx.go 同上
    service zfx_aghertz_{PkgRefName}_{svcLower}_adpinit.go internal/adpgen/adpinit/
    hertz (client) service aghertz_{svcLower}_client.go internal/adpgen/hertz/{svcLower}/
    service (service) service agservice_{svcLower}.go internal/service/
    service agservice_{svcLower}_proxy.go internal/svcgen/
    package_group zfx_agservice_proxy_{PkgRefName}.go internal/svcgen/
    module zfx_service.go internal/svcgen/

    {svcLower} = strings.ToLower(ServiceInfo.ServiceName)，如 UserService → userservice

    {PkgRefName} = PkgInfo.PkgRefName，如 student

    4.3 命名规则详解¶

    以 proto 定义 package api.student; + option go_package = "xxx/api/student"; + service UserService { ... } 为例：

    属性 值 来源
    PkgName api.student package 声明
    PkgRefName student path.Base(go_package)
    ServiceName UserService Go 命名
    ServiceName (lower) userservice strings.ToLower()

    生成的 kitex 服务端文件路径： 

    internal/adpgen/kitex/userservice/agkitex_userservice_server.go
                              └── svcLower ──────┘

    生成的 adpinit 文件路径： 

    internal/adpgen/adpinit/zfx_agkitex_student_userservice_adpinit.go
                          └── PkgRefName ── svcLower ──┘

    生成的接口文件路径： 

    api/student/agserver_student_interface.go
  └── PkgRefName ──┘

    4.4 Agent 文件的路径差异¶

    agent 文件（_fx.go、_adpinit.go、zfx_* 等）用于注册 FX 模块，它们的路径遵循按功能分层而非按包分层：

    • internal/svcgen/ — 所有 service 相关的 FX 注册文件
    • internal/adpgen/adpinit/ — 所有适配器初始化注册文件

    五、模板渲染机制¶

    5.1 模板函数¶

    定义在 types/template_func.go 中，全局注册：

    函数 功能
    ToLower 字符串小写
    ToUpper 字符串大写
    DateTimeNow 当前时间
    add/sub/mul/div 数学运算
    join 字符串连接
    contains 字符串包含

    5.2 模板数据流¶

    GennerInfo（模板数据）
    │
    ├── .GlobalInfo.PackageGroups     ← 全部包信息
    ├── .PkgInfo                      ← 当前包信息
    ├── .PackageGroup                 ← 当前包组
    ├── .PackageInfo                  ← 当前文件信息
    ├── .ServiceInfo                  ← 当前服务信息（循环中）
    │     ├── .ServiceName
    │     ├── .PkgInfo.PkgRefName
    │     ├── .Methods[]
    │     │     ├── .Name / .RawName
    │     │     ├── .Args[0].Type / .RawType
    │     │     ├── .Resp.Type / .RawType
    │     │     ├── .HttpDescs[].Path
    │     │     └── .StreamingMode()
    │     └── .HasStreaming
    │
    ├── .GenPkgRefName                ← 目标包名（用于 package 声明）
    ├── .GenScope                     ← 当前 Scope
    ├── .Imports                      ← 动态注入的 import
    ├── .Source                       ← 源文件列表
    ├── .PluginName                   ← 插件名
    └── .Versions                     ← 版本信息

    5.3 动态 Import¶

    每个 Task 可以指定 SetImport 回调，在渲染前向 GennerInfo.Imports 注入需要的 import 路径：

    SetImport: func(geni *types.GennerInfo) error {
    geni.AddImport("context", "context")
    geni.AddImport("", "gitlab.com/xxx/api/student")   // 无别名
    geni.AddImport("agkitex", "gitlab.com/xxx/contribute/agkitex") // 有别名
    return nil
}

    通用模板 Tpl_import 自动将 Imports 渲染为 Go import 块。

    六、插件注册与执行流程¶

    protoc-gen-go-xxx 插件启动
    │
    ├── flag.Parse() → 读取 model 参数
    │
    ├── protogen.Options.Run(func(gen *protogen.Plugin) error {
    │     │
    │     ├── protoc.Parse(gen, files)
    │     │     → GennerInfo（含完整类型树）
    │     │
    │     ├── gennerInfo.SetPluginName("go-agserver")
    │     ├── gennerInfo.SetBaseVersion("go-agserver", "1.0.0")
    │     │
    │     ├── gennerInfo.Reset()
    │     ├── gennerInfo.ResetVersion()
    │     │
    │     └── generator.GenRender(gennerInfo, xxxGenServiceTask(model))
    │           → 遍历 Scope → 收集 Tasks → 渲染 → 写入文件
    │})

    GenRender 对每个 GennerInfo 只调用一次。如果同一个插件需要生成不同 Scope 的文件（如 genagservice 同时生成 service 级、package_group 级和 module 级文件），它在 GenServiceTask() 中注册多个 Scope 的生成器：

    // genagservice/genner.go
func GenServiceTask() *generator.TaskGenerators {
    genners := &generator.TaskGenerators{}
    genners.AddGen(types.ScopeService, ServiceScopeTaskGen)        // service 级
    genners.AddGen(types.ScopePackageGroup, PackageGroupScopeTaskGen) // 包组级
    genners.AddGen(types.ScopeModule, ModuleScopeTaskGen)          // 模块级
    return genners
}

    七、与其他模块的关系¶

    aggo proto CLI
    │
    ├── → 调用 protoc
    │     ├── protoc-gen-go           → 标准 protobuf Go（不经过 aggen）
    │     ├── protoc-gen-go-agapi     → aggen.Parse + genapi
    │     ├── protoc-gen-go-agserver  → aggen.Parse + genserver
    │     ├── protoc-gen-go-agkitex   → aggen.Parse + genkitex
    │     ├── protoc-gen-go-aghertz   → aggen.Parse + genhertz
    │     ├── protoc-gen-go-agservice → aggen.Parse + genagservice
    │     └── protoc-gen-openapi      → 不经过 aggen
    │
    └── 输出目标代码
          ├── api/                → 接口定义（pb.go + interface.go）
          ├── internal/adpgen/    → 协议适配层（kitex/hertz 适配器）
          ├── internal/svcgen/    → Service 代理层
          └── internal/service/   → 业务逻辑（入口，不覆盖）

    生成的 adapter 代码基于 contribute/agkitex、contribute/aghertz 等封装的运行库运行。生成的 service proxy 代码基于 ag/ag_service 框架构建。
