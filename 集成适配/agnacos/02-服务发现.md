# 服务发现

> 路径：`agnacos/naming/` | Nacos 服务发现客户端，供 agkitex Resolver 消费

## 配置结构

```go
// naming/nacos_properties.go:11-24
type NacosNamingProperties struct {
    Enable bool
    common.SCProperties             // 连接信息：ServerAddr/NameSpace/UserName/Password
}
```

使用与配置中心相同的 `SCProperties` 结构，但**配置前缀不同**：

```yaml
nacos:
  naming:
    enable: true
    serveraddr: 192.168.1.1:8848
    namespace: aic-dev
    username: nacos
    password: nacos
```

如果不需要远程配置中心，只需服务发现，只需配置 `nacos.naming` 的前缀。

### 默认值

```go
// naming/nacos_properties.go:26-31
func defaultNacosNamingProperties() *NacosNamingProperties {
    return &NacosNamingProperties{
        Enable:       true,       // Enable 默认打开
        SCProperties: common.DefaultSCProperties(),
    }
}
```

`common.DefaultSCProperties()` 默认：
| 字段 | 默认值 |
|------|--------|
| Schema | `http` |
| ContextPath | `/nacos` |
| LogLevel | `error` |

ServerAddr 和 NameSpace 无默认值，必须在 YAML 中配置。

## 客户端创建

```go
// naming/naming.go:23-55
func NewNacosNamingClient(p *NacosNamingProperties) (naming_client.INamingClient, error)
```

流程：

```
NewNacosNamingClient(p)
    │
    ├── p == nil || !p.Enable → 返回 nil, nil（静默跳过）
    │
    ├── common.BuildServerConfig(p.SCProperties)
    │     └── ServerAddr → ServerAddr 逗号分隔 → ServerConfig[]
    │     └── Schema/ContextPath → ServerOption
    │
    ├── common.BuildClientConfig(p.SCProperties)
    │     └── NameSpace/UserName/Password → ClientOption
    │     └── LogLevel → ClientOption
    │
    └── clients.NewNamingClient(vo.NacosClientParam{
            ClientConfig:  cc,
            ServerConfigs: sc,
        })
          → 返回 INamingClient（SDK 官方接口）
```

**接口**：`github.com/nacos-group/nacos-sdk-go/clients/naming_client.INamingClient`

## Kitex 集成：AgNacosResolver

agnacos 的 naming 客户端是 **被消费者**——它在 agkitex 的 Resolver 中被使用：

```
// agkitex/client/resolver.go
AgNacosResolver
    │
    ├── 依赖 INamingClient（由 agnacos/naming 创建）
    │
    ├── Resolve(ctx, target) → []*discovery.Instance
    │     └── iClient.SelectOneHealthyInstance(serviceName)
    │
    └── 实现 kitex discovery.Resolver 接口
```

```go
// 使用示例（在 FX 模块中）
fx.Module("kitex-client",
    fxNacosNamingMode,     // 提供 INamingClient
    fx.Provide(
        NewAgNacosResolver,   // 注入 INamingClient → 创建 Resolver
    ),
)
```

Kitex 的 Resolver 将 INamingClient 每次 SelectOneHealthyInstance/Vo.SelectInstances 的调用结果转为 Kitex 的 Instance 格式，从而实现 Kitex 客户端通过 Nacos 选择服务端点。

## 使用示例

```go
// 手动创建
p, _ := naming.NewNacosNamingProperties(binder)
iClient, _ := naming.NewNacosNamingClient(p)

// iClient 可注入 Kitex Resolver
resolver := agkitex.NewAgNacosResolver(iClient)

// 或通过 FX（推荐）
fx.Module("app",
    fxNacosNamingMode,
    // ... agkitex 模块自动注入 Resolver
)
```

## 注意事项

- **静默跳过**：Enable=false 时返回 `nil, nil`，调用方需处理 nil 情况
- **ServerAddr 为空**：会返回错误 `"nacos server addr is empty"`，阻断启动
- **INamingClient 是 SDK 接口**：`naming/` 只负责创建，不封装 SelectInstances 等调用——真正的服务发现 API 调用在 agkitex 的 AgNacosResolver 中实现
- **config 和 naming 共用连接**：如果同时使用配置中心和服务发现，`SCProperties` 在两个前缀下各自配置，连接地址应该一致
